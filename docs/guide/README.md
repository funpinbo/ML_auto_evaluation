# AI-DLC Monitor 사용자 가이드

> 대상: VSCode 에서 Claude Code 로 `/aidlc-run` 을 돌리는 AI-DLC 운영자(user/01 §4). 근거: user/01, `workspace/project/stories/`, 실제 구현(화면 코드·API 실행 확인). **구현되지 않은 기능은 쓰지 않았습니다.** 아래 중 "미검증" 이라고 적은 부분은 사람이 실제 PC 에서 확인하기 전입니다.

## 1. 소개
AI-DLC Monitor 는 지금 AI-DLC 가 몇 단계인지, 어떤 Task 를 어느 팀이 하고 있는지, Claude 5시간 사용 한도를 얼마나 썼는지를 브라우저 한 화면에서 보여 줍니다. 실행 중인 `/aidlc-run` 루프를 현재 Task 가 끝난 뒤 멈췄다가 다시 이어 가는 일시정지/재개도 할 수 있습니다. 내 PC 에서만 동작하고(`127.0.0.1`), 로그인은 없습니다.

## 2. 시작하기
1. Python 3.11 이상을 설치합니다(Node 는 필요 없습니다).
2. 저장소 루트에서 한 번 실행합니다.
   - Windows: `run.bat` 더블클릭
   - macOS / Linux: `./run.sh`
   - 어디서나: `python run.py`
3. 처음에는 패키지를 설치하느라 시간이 걸립니다. 서버가 뜨면 브라우저가 `http://127.0.0.1:8765/` 를 자동으로 엽니다. 두 번째부터는 설치를 건너뜁니다.
4. 끄려면 실행한 콘솔에서 `Ctrl+C`.

옵션과 자세한 동작은 [monitor/README.md](../../monitor/README.md) 를 보세요.

처음 화면에서 볼 것 세 가지(위쪽 카드 한 줄):
- **파이프라인 단계** — 지금 0~6 단계 중 어디인지
- **현재 Task** — 어떤 Task 를 어느 팀이 하고 있는지
- **5시간 한도** — 사용률 %

## 3. 기능별 사용법

### 3.1 파이프라인 단계 현황 (FR-001)
- 언제 쓰나요: AI-DLC 가 `init → interpret → analyze → teams → plan → run → docs` 중 어디까지 왔고 다음에 무슨 명령을 쳐야 하는지 볼 때.
- 사용 방법: 첫 화면 `파이프라인 단계` 카드에 `번호 · 이름` 과 `다음: <명령>` 이 나옵니다. **파이프라인 단계** 패널에는 7단계 각각의 `완료` / `진행` / `대기` / `알 수 없음` 과 명령이 나열되고 현재 단계가 강조됩니다. 오른쪽에는 user / project / docs 문서 검사(Gate)의 `PASS`/`FAIL` 이 있고, FAIL 이면 미작성·누락 개수가 함께 나옵니다.
- 알아둘 점 / 제한:
  - 현재 단계 = 완료가 아닌 가장 앞 단계입니다. 모든 단계가 끝나면 `모든 단계 완료`.
  - 단계를 판정하는 기준(어떤 파일이 있으면 완료인지)은 아직 **가정**이며 PO 화면 리뷰로 확정되기 전입니다(미검증).
  - 화면은 상태를 읽기만 합니다. 명령을 대신 실행하지는 않습니다.

### 3.2 Phase · Task 진행률 (FR-002)
- 언제 쓰나요: Phase 가 얼마나 진행됐는지, 특정 팀의 Task 가 무엇인지 볼 때.
- 사용 방법:
  1. `Phase N 진행률` 카드와 **Plan · Phase 진행률** 패널에서 Phase 별 `완료 / 전체` 와 %(소수점은 내림)를 봅니다.
  2. **Task 목록** 에서 `모든 Phase` / `모든 팀` / `모든 상태` 드롭다운으로 거릅니다(조건은 모두 만족해야 표시). 오른쪽 `N / M` 은 보이는 개수/전체입니다.
- 알아둘 점 / 제한:
  - 상태는 `완료` / `진행 중` / `대기` / `막힘` 네 가지입니다. 같은 Task 가 완료이면서 `Blocked` 에도 있으면 `완료` 가 우선합니다.
  - `tasks.md` 가 없으면 "Task 목록이 없습니다 — `/aidlc-plan` 을 실행하세요" 안내가 나옵니다. 파일이 깨졌으면 이 패널만 오류를 표시하고 나머지는 정상입니다.

### 3.3 메모리 상태 (FR-003)
- 언제 쓰나요: 지금 어떤 Task 가 열려 있는지, 메모리 갱신(cascade)이 밀려 있는지 볼 때.
- 사용 방법: 첫 화면 `현재 Task` 카드에 Task ID, `[팀]`, 경과 시간이 나옵니다. 진행 중인 Task 가 없으면 `대기` / `STM idle`. **메모리 상태** 패널에는 STM 상태, Task, 시작 시각, 경과, LTM·Tasks 리비전, 아카이브 수가 있습니다.
- `미처리 cascade` 읽는 법:

  | 표시 | 뜻 |
  |------|-----|
  | 없음 | 메모리가 모두 반영됨 |
  | 1/3 LTM 갱신 필요 | 닫힌 STM 이 장기 메모리(LTM)에 아직 반영되지 않음 |
  | 2/3 Task 갱신 필요 | LTM 이 바뀌었는데 tasks.md 가 따라오지 않음 |
  | 3/3 Plan 갱신 필요 | Phase 가 모두 끝났는데 plan.md 에 완료로 적히지 않음 |

- 알아둘 점 / 제한: 이 화면은 읽기만 합니다. cascade 는 Claude Code 가 처리해야 하며 화면에서 처리하지 않습니다. 일시정지된 상태에서는 STM `idle`, cascade `없음` 이 정상입니다.

### 3.4 Claude 사용량 (FR-004)
- 언제 쓰나요: 5시간·7일 한도에 얼마나 가까운지, 토큰이 어디에 쓰였는지 볼 때.
- 사용 방법: 첫 화면 `5시간 한도` 카드와 **Claude 사용량** 패널의 게이지에서 사용률(%, 반올림)과 초기화 시각을 봅니다. 아래에는 오늘 응답·입력·출력 토큰, 캐시 적중률, 세션 비용, 컨텍스트 사용률과, 시간대별·모델별 토큰 그래프가 있고 기간 탭(`5h` / `24h` / `7d` / `30d`)으로 바꿀 수 있습니다.
- 알아둘 점 / 제한:
  - 한도 %는 Claude Code 의 status line 신호에서 옵니다. 신호가 없으면 `한도 정보 없음` 안내가 나오지만 토큰 집계는 계속 보입니다. 신호가 10분 넘게 갱신되지 않으면 "N분 전 기준" 경고가 붙습니다.
  - 서버를 막 켠 직후에는 `사용량 집계 중 NN%` 가 보입니다. 끝나기 전에도 값은 부분적으로 나옵니다.
  - 그래프는 이 프로젝트의 Claude Code 기록만 집계합니다. 대화 내용은 읽지 않고 토큰 수치만 읽습니다.
  - 실제 Claude Code 세션에서 한도 %가 갱신되는 것은 **미검증**입니다.

### 3.5 루프 일시정지 / 재개 (FR-005)
- 언제 쓰나요: `/aidlc-run N` 루프를 안전하게 쉬었다 가고 싶을 때.
- 사용 방법:
  1. 루프 카드/**루프 제어** 패널이 `실행 중` 인지 봅니다.
  2. `⏸ 일시정지` → `일시정지 요청됨 (현재 Task 진행 중)`. 현재 Task 와 메모리 갱신이 끝까지 진행됩니다.
  3. `일시정지됨 (세션 대기 중)` 이 되면 안전하게 멈춘 상태입니다. 남은 허용 시간(기본 2시간)이 보입니다. Claude Code 창은 닫지 마세요.
  4. `▶ 재개` → `실행 중`. `/aidlc-run` 을 다시 입력하지 않고 남은 반복을 이어 갑니다.
- 화면에 나오는 상태:

  | 문구 | 뜻 |
  |------|-----|
  | 루프 없음 | 실행 중인 루프가 없음(버튼 비활성). 끝난 이유가 함께 표시됨 |
  | 실행 중 | 루프가 돌고 있음 |
  | 일시정지 요청됨 (현재 Task 진행 중) | 눌렀고, 현재 Task 가 끝나기를 기다리는 중. `▶ 재개` 로 취소 가능 |
  | 일시정지됨 (세션 대기 중) | 멈춰서 대기 중 |
  | 재개 요청됨 | 재개를 눌렀고 곧 `실행 중` 이 됨(순간적으로 보일 수 있음) |
  | 세션 없음 | 대기하던 세션이 사라짐. `/aidlc-run <남은 수>` 로 다시 실행 |

- 알아둘 점 / 제한:
  - 즉시 중단은 없습니다. 항상 Task 경계에서만 멈춥니다. 마지막 반복 중에 눌렀다면 그냥 정상 종료됩니다.
  - 일시정지 상한(기본 2시간)을 넘기면 루프가 종료되고 `일시정지 상한(2시간) 초과로 종료 — 남은 반복 N회: /aidlc-run N` 이 표시됩니다.
  - 루프가 끝난 이유는 `완료 — N회 반복을 모두 마쳤습니다` / `막힘으로 종료 — STM 의 blocker 를 확인하세요` / `선택 가능한 Task 가 없어 종료` / 위 상한 초과 중 하나로 표시됩니다.
  - 화면에서 `/aidlc-run` 을 시작하거나 반복 수를 바꿀 수는 없습니다.
  - 이 기능이 쓰는 파일은 `workspace/memory/.control.json` 뿐입니다. 이 파일이 깨졌다면 "제어 파일을 읽을 수 없음 — 일시정지를 다시 누르면 새로 씁니다" 경고가 나오고, 루프는 일시정지하지 않고 계속 진행합니다. 파일을 지운 경우는 오류가 아니라 "요청 없음" 으로 봅니다.
  - 실제 Claude Code 세션(특히 VSCode 메인 세션, Windows)에서의 일시정지/재개는 **미검증**입니다(UAT 미실행).

### 3.6 자동 갱신 (FR-008 최소)
- 파일이 바뀌면 화면이 5초 안에 알아서 갱신됩니다(`● 실시간`). 실시간 연결을 못 열면 `● 5초 폴링` 으로 바뀌어 5초마다 다시 읽습니다. `⟳` 로 수동 새로고침도 됩니다.
- 이 버전에는 타임라인·팀 현황·비용 예측 패널이 없습니다(2차 범위).

### 3.7 원클릭 실행 (SCOPE-01)
- [§2](#2-시작하기) 와 [monitor/README.md](../../monitor/README.md) 를 보세요. 포트가 사용 중이면 자동으로 다음 포트를 쓰고 콘솔에 주소를 출력합니다. 이미 떠 있으면 새 서버 없이 브라우저만 엽니다.

## 4. 자주 묻는 질문
| 질문 | 답 |
|------|-----|
| 다른 PC나 휴대폰에서 볼 수 있나요? | 아니요. `127.0.0.1` 에만 열려 있고 바꿀 수 없습니다. |
| 로그인이 필요한가요? | 없습니다. 내 PC 에서만 접속되기 때문입니다. |
| 내 대화 내용이 읽히나요? | 아니요. 사용량은 토큰 수치만 읽고 대화 본문은 읽지도 화면에 내보내지도 않습니다. |
| 화면에서 문서나 Task 를 고칠 수 있나요? | 없습니다. 화면이 쓰는 파일은 일시정지/재개 요청 파일 하나뿐입니다. |
| 주소를 `localhost` 나 다른 포트로 열었더니 오류가 나요. | 서버가 알려 준 `http://127.0.0.1:<포트>/` 로 여세요. 허용되지 않는 주소는 `BAD_HOST` 로 거절됩니다. (`localhost:<같은 포트>` 는 허용됩니다.) |
| 여러 번 실행하면 어떻게 되나요? | 이미 떠 있으면 새 서버를 만들지 않고 브라우저만 엽니다. |
| Node 를 설치해야 하나요? | 아니요. 빌드된 화면이 저장소에 들어 있습니다. |

## 5. 문제 해결
| 증상 | 원인 | 해결 |
|------|------|------|
| `Python 3.11 이상이 필요합니다` | Python 이 없거나 낮음(Windows 는 Store 별칭만 있는 경우 포함) | https://www.python.org/downloads/ 에서 3.11 이상 설치 (Windows 는 "Add python.exe to PATH" 체크) |
| "서버가 시작되지 않았습니다" | 20초 안에 서버가 응답하지 않음 | [서버가 안 뜸](../../workspace/project/ops/runbooks/server-wont-start.md) |
| 포트 사용 중 / 다른 앱이 열림 | 8765 를 다른 프로그램이 사용 | [포트 사용 중](../../workspace/project/ops/runbooks/port-in-use.md) |
| `한도 정보 없음` | status line 신호 없음(첫 응답 전, 비구독, 미실행) | [statusLine 미실행](../../workspace/project/ops/runbooks/statusline-not-running.md) |
| `일시정지됨` 이 풀리지 않음 / `세션 없음` | 재개 요청이 반영되지 않았거나 세션이 사라짐 | [일시정지가 안 풀림](../../workspace/project/ops/runbooks/pause-not-releasing.md) |
| 사용량 집계가 오래 걸림 | 첫 실행 시 최근 30일 기록을 읽는 중 | [집계가 느림](../../workspace/project/ops/runbooks/warmup-slow.md) |
| 패널 하나만 "읽을 수 없음" | 해당 소스 파일이 깨짐(다른 패널은 정상) | 해당 파일(`tasks.md`, `short-term.md` 등)의 형식 확인 |

## 6. 용어
| 용어 | 뜻 |
|------|-----|
| 단계(Stage) | AI-DLC 의 0~6 진행 단계: init, interpret, analyze, teams, plan, run, docs |
| Phase | 계획(`plan.md`/`tasks.md`)의 묶음(P1, P2 …) |
| STM | Short-term memory — 지금 하고 있는 Task 하나의 작업 메모 (`short-term.md`) |
| LTM | Long-term memory — 끝난 작업에서 모은 결정·교훈 (`long-term.md`) |
| cascade | Task 를 닫은 뒤 LTM → Task → Plan 순서로 이어지는 메모리 갱신 |
| Gate | `aidlc.py check` 로 하는 문서 완성도 검사 (user / project / docs) |
| 루프 | `/aidlc-run N` 으로 Task 를 N번 이어서 실행하는 것 |
| 일시정지 상한 | 일시정지를 유지할 수 있는 시간. 기본 2시간 |
| status line 신호 | Claude Code 가 응답 때마다 남기는 한도 % 등의 스냅샷 파일 |
