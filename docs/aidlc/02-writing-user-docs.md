# 2. 사용자 문서 작성법 (User Layer)

User Layer 는 **사용자만 쓰는** 4개 문서입니다. Agent 는 이 문서를 읽고 해석만 하며 고치지 않습니다. 문서 품질이 이후 모든 결과물의 품질을 결정합니다.

## 표기 규칙
| 표기 | 의미 |
|------|------|
| `{{ ... }}` | **필수 항목.** 하나라도 남아 있으면 `/aidlc-interpret` 가 진행되지 않습니다. 괄호째 지우고 내용을 씁니다. |
| `<!-- ... -->` | 작성 가이드(주석). 지우지 않아도 되며 검사에서 무시됩니다. |
| `N/A (이유)` | 해당 없음. 빈칸 대신 이렇게 쓰면 Agent 가 의도적인 공백으로 이해합니다. |
| frontmatter `version` | 문서를 크게 고치면 올려 주세요. 해석서가 어떤 버전을 읽었는지 기록합니다. |

## 01. 프로젝트 개요 & 기능 요구서
**"무엇을, 누구를 위해, 왜"** 를 정의합니다.

| 절 | 핵심 | 좋은 예 | 나쁜 예 |
|----|------|---------|---------|
| 1 배경 | 해결할 문제를 숫자로 | "상담 문의의 60%가 반복 질문, 평균 대기 12분" | "고객 경험 개선" |
| 2 KPI | 현재 값·목표 값·측정 방법 | "1차 해결률 0% → 40%, 상담원 연결 로그로 측정" | "만족도 향상" |
| 3 범위 | Out of scope 를 꼭 적기 | "음성 상담은 이번 범위 아님" | (비워 둠) |
| 5 FR | 수용 기준은 Given/When/Then | "Given FAQ 에 있는 질문 When 질문 Then 3초 내 근거 링크와 답변" | "잘 대답한다" |
| 6 NFR | 측정 가능한 수치 | "p95 3초, 가용성 99.5%" | "빠르게" |

**팁**
- FR 우선순위는 MoSCoW(Must/Should/Could/Won't). Must 가 너무 많으면 MVP 가 커집니다.
- 수용 기준은 QA 팀이 그대로 테스트로 바꿉니다. "테스트할 수 있는가?" 로 점검하세요.
- 모르는 건 §10 오픈 이슈에 솔직하게. Agent 가 질문으로 정리해 줍니다.

## 02. 개발 표준 정의서
모든 팀 Agent 의 **최상위 규칙**입니다. 팀 charter 는 이 문서를 구체화만 하고 어길 수 없습니다.

- **§1 언어·런타임** — 버전까지. "Python" 말고 "Python 3.12".
- **§5 테스트 / §10 DoD** — STM 의 `outcome: done` 판정 기준이자 QA 리뷰 게이트의 기준입니다. 구체적일수록 좋습니다.
- **§6 API 규칙** — 에러 포맷, 인증, 버저닝. `/aidlc-docs` 가 API 가이드를 쓸 때 명세와 대조하는 기준입니다.
- **§11 AI Agent 작업 규칙** — Agent 가 사람 승인 없이 하면 안 되는 일(운영 배포, DB 마이그레이션 실행 등). 여기 적힌 작업은 Agent 가 `blocked` 로 멈추고 보고합니다.

## 03. 아키텍처 철학
"무엇을 만들까" 가 아니라 **"결정이 갈릴 때 무엇을 우선하나"** 입니다.

- **§1 원칙** — 위에 있을수록 우선. 3~7개.
- **§2 품질 속성 순위** — 1~7 동순위 없이. architecture-analyst 가 후보 아키텍처를 `가중치 = 8 - 순위` 로 채점합니다.
- **§4 금지 기술** — 여기 적으면 Agent 가 쓰지 않습니다.
- **§9 ADR 필수 대상** — 이 결정들은 반드시 ADR 문서가 남습니다.

> 순위가 충돌하면(예: 비용 1위인데 NFR 이 99.99% 가용성) 해석 단계에서 "충돌"로 잡혀 HOLD 됩니다. 의도된 것이 아니라면 둘 중 하나를 고치세요.

## 04. 데이터 정의서
data-analyst 가 EDA 를 하는 입력입니다.

- 데이터 파일은 `workspace/data/` 에 두고 §1 위치에 경로를 적으세요.
- 아직 데이터가 없으면 §1 에 `N/A (데이터 없음 — 생성 예정)` 이라고 쓰고 §2 예상 엔티티를 채우면, "가설 기반 분석" 으로 진행됩니다.
- **§3 분석 질문**이 가장 중요합니다. "문의 유형 상위 10개는 전체의 몇 %인가?" 처럼 비즈니스 질문으로.
- **§6 개인정보** — 포함 시 Agent 는 분석 전에 마스킹하고 원본 값을 출력하지 않습니다.

## 고친 뒤에는
User 문서를 고치면 `/aidlc-interpret` 를 다시 실행해 해석서를 갱신하세요. 분석 이후 단계에 큰 영향을 주는 변경이면 `/aidlc-analyze` 부터 다시 돌립니다.
