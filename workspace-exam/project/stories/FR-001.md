# FR-001 파이프라인 단계 현황

## 1. 사용자 스토리
AI-DLC 운영자로서 AI-DLC 가 0~6 단계 중 어디에 있는지 보고 싶다, 다음에 무엇을 할지 알기 위해. (01 §5 원문)

- KPI: **KPI-01 Q1 "지금 몇 단계인가"** 의 유일한 답 (10 §3). 첫 화면 상단 행에 "현재 단계" 를 둔다.
- API: `GET /api/v1/pipeline` (20 §5). 필드 이름·enum 은 backend/architecture 가 정하되 아래 상태와 1:1 로 대응해야 한다.

## 2. 단계 판정 규칙 (A11 최종안 — 가정)
> 00 A11 가정을 실제 프레임워크 동작(`aidlc.py init` 이 user·memory 템플릿을 복사, `/aidlc-plan` 이 tasks `rev: 1` 설정, `check docs` 의 동작)과 대조해 다듬은 **product 확정안**이다.
> PO(funpinbo) 화면 리뷰(T-014 UAT)로 확정되기 전까지 이 절의 모든 수용 기준은 **가정**이다.

### 2.1 상태 4종
| 상태 | 화면 라벨 | API 값(권고) | 의미 |
|------|-----------|--------------|------|
| 완료 | `완료` | `done` | 완료 조건 D 충족 |
| 진행 | `진행` | `in_progress` | D 미충족, 진행 조건 S 충족 |
| 대기 | `대기` | `waiting` | D·S 모두 미충족 |
| 확인 불가 | `확인 불가` | `unknown` | 판정에 필요한 파일이 깨져 D/S 를 계산할 수 없음 (NFR-002) |

### 2.2 단계별 조건
경로는 저장소 루트 기준. "존재" = 일반 파일로 존재. Phase/체크박스/미처리 cascade 판정은 Hook(`memory_cascade.py`)의 `PHASE_RE`·`CHECKBOX_RE`·`Memory.phases()`·`Memory.pending()` 과 **같은 결과**여야 한다(ADR-009).

| # | 단계 (다음 명령) | 완료 조건 D | 진행 조건 S (D 가 아닐 때) |
|---|------------------|-------------|------------------------------|
| 0 | init (`/aidlc-init`) | `workspace/user/` 에 `aidlc/templates/user/` 와 같은 이름의 문서 4개(01~04) **와** `workspace/memory/` 에 `short-term.md`·`long-term.md`·`plan.md`·`tasks.md` 4개가 모두 존재 | 위 8개 중 1개 이상 존재 |
| 1 | interpret (`/aidlc-interpret`) | `workspace/project/00-interpretation.md` 존재 **and** 이 파일의 미작성 플레이스홀더 0개 **and** §6 의 `- 결정:` 줄이 GO **and** user Gate PASS | `00-interpretation.md` 존재 |
| 2 | analyze (`/aidlc-analyze`) | `workspace/project/` 에 `10-business-analysis.md`·`20-architecture-analysis.md`·`30-data-analysis.md` 3개 모두 존재 | 3개 중 1개 이상 존재 |
| 3 | teams (`/aidlc-teams`) | `workspace/project/40-team-composition.md` 존재 **and** frontmatter `teams` 가 비어 있지 않은 목록 **and** 목록의 모든 id 에 대해 `workspace/teams/<id>/charter.md` 존재 | `40-team-composition.md` 존재, 또는 `workspace/teams/*/charter.md` 1개 이상 |
| 4 | plan (`/aidlc-plan`) | `workspace/memory/tasks.md` frontmatter `rev` ≥ 1 **and** `## P<n>` 섹션 중 체크박스 Task 가 1개 이상인 섹션이 있음 | `tasks.md` `rev` ≥ 1 (Task 없음) |
| 5 | run (`/aidlc-run`) | 단계 4 의 D 충족 **and** Task 가 있는 모든 `## P<n>` 섹션이 전부 `[x]` **and** `Memory.pending()` 이 없음 **and** STM `status` ≠ `active` | `## P<n>` 섹션에 `[x]` 1개 이상, 또는 STM `status` ∈ {active, closed}, 또는 `workspace/memory/archive/STM-*.md` 1건 이상 |
| 6 | docs (`/aidlc-docs`) | docs Gate PASS **and** `docs/README.md` 존재 | `docs/` 아래 `docs/aidlc/` 를 제외한 `.md` 파일 1개 이상 |

세부 규칙:
- **R1 (독립 판정)** 각 단계는 자기 조건으로만 판정한다. 뒤 단계가 완료여도 앞 단계 상태를 바꾸지 않는다(예: P1 문서화 후 6 = 완료, 5 = 진행 가능).
- **R2 (현재 단계)** 현재 단계 = 상태가 `완료` 가 아닌 가장 작은 번호의 단계. 화면은 현재 단계를 강조하고 "다음: `<명령>`" 을 함께 보여 준다. 0~6 이 모두 완료면 현재 단계 = `6 docs` + `전체 완료`.
- **R3 (GO 판정)** 00 §6 의 첫 `- 결정:` 줄에서 `결정:` 뒤의 `*`·공백을 제거한 첫 단어가 `GO` 이면 GO, `HOLD` 이면 HOLD, 그 밖(템플릿의 `GO / HOLD` 플레이스홀더 포함)은 미결정으로 보고 D 미충족.
- **R4 (템플릿 tasks 구분)** `aidlc.py init` 이 복사한 템플릿 `tasks.md` 는 `rev: 0` 에 예시 Task 를 1개 갖는다. `rev` ≥ 1 조건이 있으므로 init 직후 단계 4 는 `대기` 다.
- **R5 (docs Gate 빈 대상)** `aidlc.py check docs` 는 `docs/` 에 검사 대상 파일이 0개여도 PASS(exit 0)를 낸다(2026-10-23 이 저장소에서 확인). 그래서 단계 6 의 D 에 `docs/README.md` 존재를 추가한다(`/aidlc-docs` 가 항상 생성하는 파일).
- **R6 (깨진 입력)** 판정에 필요한 파일이 UTF-8 이 아니거나 frontmatter 를 읽을 수 없으면 해당 단계만 `확인 불가`. R2 에서 `확인 불가` 는 완료가 아닌 것으로 본다.
- **R7 (팀 확인 범위)** 단계 3 은 `workspace/` 안 파일만 본다. `.claude/agents/team-<id>.md` 존재는 판정에 쓰지 않는다(`/aidlc-teams` 스킬의 검증과의 차이 — §8 참고).

### 2.3 Gate 3종
| Gate | 실행 | 표시 |
|------|------|------|
| user / project / docs | `aidlc.py check <layer>` 서브프로세스(`sys.executable`, timeout 10 s, ADR-009 §5). `status` 는 어떤 경로로도 실행하지 않는다(D-07) | `PASS`/`FAIL`, 미작성 N개, 누락 문서 M개, 확인 시각 |

- PASS/FAIL = exit code 0/≠0. 미작성·누락 수 = 마지막 줄 `GATE (PASS|FAIL) — <layer> layer: 미작성 N개, 누락 문서 M개` 의 N·M.
- 대상 디렉터리가 없으면(출력에 GATE 줄 없음, exit 1) → `FAIL` + "대상 없음" (수치는 `-`).
- 10 s 초과 → `확인 불가 (GATE_TIMEOUT)`. PASS/FAIL 로 표시하지 않는다.
- docs Gate 가 검사 대상 0개로 PASS 이면 "검사 대상 문서 없음" 을 함께 표시한다(R5).

## 3. 수용 기준 (Given/When/Then)
> 모든 AC 는 §2 규칙에 의존하므로 **가정(A11)**. fixture 는 qa 의 `workspace_factory` 등으로 Given 을 만든다.

- **AC-1 (빈 workspace)** Given `workspace/` 만 있고 하위 파일이 없을 때 When `/api/v1/pipeline` 을 조회하면 Then 단계 0~6 이 모두 `대기`, 현재 단계 = 0 init, "다음: `/aidlc-init`" 이 표시되고 HTTP 200 이다.
- **AC-2 (init 직후)** Given `aidlc.py init` 결과와 같은 파일 구성(user 템플릿 4개 + memory 템플릿 4개, tasks `rev: 0`)일 때 Then 0 = `완료`, 1~6 = `대기`, user Gate = `FAIL` 이고 미작성 수가 `aidlc.py check user` 출력의 N 과 같다.
- **AC-3 (부분 init)** Given memory 4개 중 `tasks.md`·`short-term.md` 만 있고 user 문서가 없을 때 Then 0 = `진행`.
- **AC-4 (해석 HOLD)** Given 00 이 있고 §6 결정이 HOLD 일 때 Then 1 = `진행`. Given 결정 줄이 템플릿 그대로(`GO / HOLD` 플레이스홀더)일 때 Then 1 = `진행`.
- **AC-5 (해석 GO 이지만 user Gate FAIL)** Given 00 결정 GO, 00 미작성 0개, user Gate FAIL 일 때 Then 1 = `진행` (R1 에 따라 2 이후는 각자 판정).
- **AC-6 (해석 완료)** Given 00 결정 GO, 00 미작성 0개, user Gate PASS 일 때 Then 1 = `완료`.
- **AC-7 (분석 일부)** Given 10·20 만 있을 때 Then 2 = `진행`. Given 10·20·30 이 모두 있을 때 Then 2 = `완료`.
- **AC-8 (팀)** Given 40 frontmatter `teams: [product, qa]` 이고 `workspace/teams/product/charter.md` 만 있을 때 Then 3 = `진행`. Given 두 charter 가 모두 있을 때 Then 3 = `완료`. Given `teams: []` 일 때 Then 3 = `진행`.
- **AC-9 (plan)** Given tasks `rev: 1` 이고 `## P1` 에 Task 1개 이상일 때 Then 4 = `완료`. Given tasks `rev: 1` 이고 Task 0개일 때 Then 4 = `진행`.
- **AC-10 (run 진행)** Given 4 완료, `## P1` 에 `[x]` 1개 이상 `[ ]` 1개 이상일 때 Then 5 = `진행`. Given 4 완료, `[x]` 0개, STM `active` 일 때 Then 5 = `진행`. Given 4 완료, `[x]` 0개, STM `idle`, archive 0건일 때 Then 5 = `대기`.
- **AC-11 (run 완료 경계)** Given 모든 Phase 섹션이 전부 `[x]` 이지만 plan `completed_phases` 에 해당 Phase 가 없어 `Memory.pending().level == "plan"` 일 때 Then 5 = `진행`. Given 같은 상태에서 `completed_phases` 에 모든 Phase 가 있고 STM `idle` 일 때 Then 5 = `완료`.
- **AC-12 (docs)** Given `docs/` 에 `docs/aidlc/` 만 있을 때 Then docs Gate 는 `PASS` + "검사 대상 문서 없음", 6 = `대기`. Given `docs/README.md` 가 있고 docs Gate PASS 일 때 Then 6 = `완료`. Given `docs/guide/README.md` 에 미작성 플레이스홀더 1개가 있을 때 Then docs Gate `FAIL`(미작성 1개), 6 = `진행`.
- **AC-13 (현재 단계)** Given 0~4 완료, 5 진행, 6 완료일 때 Then 현재 단계 = 5 run, "다음: `/aidlc-run`" 이 표시된다. Given 0~6 모두 완료일 때 Then "전체 완료" 가 표시된다.
- **AC-14 (Gate 일치)** Given 임의의 fixture 에서 When pipeline 을 조회하면 Then user·project·docs Gate 의 PASS/FAIL·미작성 수·누락 문서 수가 같은 fixture 에서 `aidlc.py check <layer>` 를 직접 실행한 exit code·마지막 줄 수치와 100% 같다.
- **AC-15 (Gate 대상 없음/시간 초과)** Given `docs/` 가 없을 때 Then docs Gate = `FAIL` + "대상 없음". Given Gate 서브프로세스가 10 s 를 넘길 때(테스트에서 주입) Then 그 Gate 만 `확인 불가` + `GATE_TIMEOUT`, 나머지 Gate·단계는 정상 표시, HTTP 200.
- **AC-16 (깨진 파일)** Given `tasks.md` 가 UTF-8 이 아닐 때 Then 4·5 = `확인 불가`, 패널 `meta.status = partial` 과 경고 1건, 다른 단계는 정상 판정, HTTP 500 0건.
- **AC-17 (읽기 전용)** Given `closed_stm_workspace` 일 때 When pipeline 을 반복 조회하면 Then 조회 전후 workspace 해시가 같고 `short-term.md` 가 초기화되지 않는다(`status` 미실행, D-07).
- **AC-18 (첫 화면)** Given 대시보드 첫 화면을 열었을 때 Then 현재 단계(번호·이름·상태)가 스크롤·클릭 없이 상단 행에 보인다 (KPI-01 Q1, UAT 로 확인).
- **AC-19 (성능)** Given Task 100개 workspace 에서 When 접속하면 Then 파이프라인 패널 REST 응답이 첫 화면 2초 기준(P-01) 안에 온다. Gate 결과는 TTL 5 s 캐시를 써도 된다.

## 8. 미결·메모
