# 10. 비즈니스 모델 분석

> 입력: 00-interpretation.md, user/01. 출력은 아키텍처·팀 구성·Plan 의 우선순위 근거가 됩니다.
>
> **전제:** AI-DLC Monitor 는 무료·로컬·단일 사용자 개발 도구로 **수익이 없다**. 따라서 "비즈니스 가치"는 (1) AI-DLC 운영자의 시간 절약, (2) 사용량 한도 기습 소진 방지, (3) 진행 중 Task 를 망가뜨리지 않는 안전한 일시정지, (4) AI-DLC 프레임워크의 **레퍼런스 예시 프로젝트**로서의 문서·코드 품질로 정의한다. 시장/경쟁 수치는 웹 검색을 하지 않았으며, 수치는 모두 01 원문 또는 "가정"으로 표기한다.

## 1. 가치 제안 (Value Proposition)
| 고객 세그먼트 | 해결하는 Job | 없애는 Pain | 주는 Gain |
|---------------|-------------|------------|-----------|
| AI-DLC 운영자 (VSCode + Claude Code 로 `/aidlc-run N` 을 혼자 돌리는 개발자, 01 §4) | 루프가 어디까지 왔는지, 지금 어떤 Task 를 어느 팀이 하는지 파악 | 터미널 `/aidlc-status` + `workspace/memory/*.md` 직접 열기로 약 1분 소요 (01 §2 KPI-01 현재 값) | 브라우저 첫 화면 한 장으로 5초 이내 파악 (FR-001·002·003) |
| AI-DLC 운영자 | 사용량 한도에 걸리기 전에 작업량을 조절 | `/usage` 를 따로 열어야 하고 진행 상황과 함께 볼 수 없음 → 루프 도중 5시간/7일 한도 기습 소진 | 한도 %·초기화 시각·토큰 추이를 진행 상황 옆에서 상시 확인 (FR-004), 80% 경고 (FR-010) |
| AI-DLC 운영자 | 진행 중인 루프를 안전하게 멈추고 나중에 이어가기 | 세션을 직접 끊으면 Task 가 어중간한 상태로 남고 STM/cascade 정리를 수작업으로 해야 함 (01 §1) | Task 경계(cascade 포함)에서 멈추고 같은 세션에서 자동 재개 (FR-005) — 복구 작업 0 |
| AI-DLC 운영자 (신규 도입자) | 내려받자마자 써 보기 | Node 빌드·DB·Docker 등 설치 부담 | `run.bat`/`run.sh` 1회 실행으로 5분 이내 첫 화면 (SCOPE-01, KPI-02) |
| AI-DLC 프레임워크 사용자/학습자 (PO funpinbo 의 관심사, 01 §8) | AI-DLC 로 실제 프로젝트가 어떻게 만들어지는지 참고 | 프레임워크 문서만으로는 산출물 수준·흐름을 가늠하기 어려움 | 00~40 분석서, ADR, 팀 charter, 코드가 모두 갖춰진 **레퍼런스 예시 프로젝트** (03 §2 유지보수성 3위 "예시로 읽히는 코드") |

## 2. 비즈니스 모델 캔버스 (Lean)
| 항목 | 내용 |
|------|------|
| 고객 세그먼트 | 1차: VSCode + Claude Code(Pro/Max 구독)로 AI-DLC 를 혼자/소규모로 운영하는 개발자. 2차: AI-DLC 도입을 검토하며 예시 프로젝트를 참고하는 개발자 |
| 가치 제안 | "AI-DLC 진행 상황과 Claude 사용량을 한 화면에서, 루프는 안전하게 멈추고 이어간다" — 읽기 전용(제어 파일 1개 제외)·로컬 전용(127.0.0.1)·대화 본문 비접근 |
| 채널 | AI-DLC 저장소에 포함된 `monitor/` + 루트 `run.py`/`run.bat`/`run.sh`. 배포 서버·패키지 레지스트리 없음 (01 §3 Out of scope: 원격 배포·CI/CD) |
| 고객 관계 | 셀프 서비스. 설치·사용 안내는 `docs/` 와 대시보드 패널 내 안내 문구("한도 정보 없음", "데이터 없음")로 대체. 지원 채널 없음 |
| 수익원 / 비용 절감 효과 | **수익원: N/A (무료 로컬 도구, 과금 없음).** 비용 절감(회피) 효과로 대체: ① 상태 파악 시간 약 1분 → 5초, 루프 실행 중 하루 20회 확인 가정 시 하루 약 18분 절약 (가정) ② 한도 기습 소진으로 인한 루프 중단·재작업 회피 (FR-004·010) ③ 세션 강제 종료 후 STM/cascade 수동 복구 작업 회피 (FR-005) ④ 별도 모니터링 SaaS·서버 비용 0 (03 §4 외부 SaaS 금지) |
| 핵심 자원 | AI-DLC 의 표준화된 상태 파일(frontmatter, DS-01), `aidlc.py check/status` (DS-02), Claude Code 세션 JSONL 의 usage 필드 (DS-03), status line 스냅샷 (DS-04), 팀 charter (DS-05). 1인 개발자의 2주 개발 시간 |
| 핵심 활동 | 파일 파싱·증분 집계(읽기 전용), SSE 실시간 갱신, 루프 제어 파일 + aidlc-run 스킬의 Task 경계 대기 로직, 원클릭 설치 스크립트, 레퍼런스 수준 문서화(ADR·OpenAPI·docs) |
| 핵심 파트너 | Anthropic Claude Code (status line `rate_limits`/`cost` 제공, JSONL 기록 형식 — 공식 계약 아님, 변경 위험), 오픈소스 FastAPI·uvicorn·Pydantic·Vue 3·Vite·ECharts (MIT/Apache/BSD) |
| 비용 구조 | 인프라: 0 (로컬 단일 프로세스, DB·Docker 없음). LLM 토큰: 개발 기간 중 AI-DLC 루프 실행 토큰(구독 한도 내) + 일시정지 대기 중 약 10분마다 대기 호출 반복으로 소량 토큰 소비(Q5 허용, 최대 2시간 기본). 인력: 1인 × 2주(M1) + 1주(M2). 유지: Claude Code 기록 형식 변경 시 파서 수정 |

## 4. 사용자 여정 & 기능 매핑
| 단계 | 사용자 행동 | 접점 | Pain | 대응 FR |
|------|-------------|------|------|---------|

| 7. 재개 | 나중에 재개 버튼 → 같은 세션이 남은 반복을 이어감 | 제어 버튼 | `/aidlc-run` 재입력·남은 반복 수 계산 필요 | FR-005 |
| 8. 이상 대응 | cascade 막힘·blocked Task·한도 80% 경고를 보고 조치 | 상단 경고 배너 | 문제를 루프가 멈춘 뒤에야 발견 | FR-010, FR-003, FR-002 |
