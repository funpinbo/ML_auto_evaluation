# 03. 아키텍처 철학

> **작성자: 사용자.** "무엇을 만들까"가 아니라 **"결정이 갈릴 때 무엇을 우선하는가"** 를 적는 문서입니다.
> architecture-analyst Agent 는 후보 아키텍처를 이 우선순위로 채점합니다. `{{ }}` = 필수.

## 1. 핵심 원칙 (우선순위 순)
1. 설치·실행이 단순할 것 — 내려받고 실행 파일 하나로 웹까지 뜬다
2. 읽기 전용 우선 — 파일을 바꾸는 동작은 루프 제어(일시정지/재개)뿐이다
3. 의존성 최소 — 표준 라이브러리로 되면 라이브러리를 추가하지 않는다

## 2. 품질 속성 우선순위
| 품질 속성 | 순위 | 비고 |
|-----------|------|------|
| 개발 속도 (Time to market) | 1 | 2주 MVP |
| 성능 (Latency/Throughput) | 5 | |
| 가용성/신뢰성 | 4 | 파일이 깨져도 죽지 않을 것 |
| 보안 | 2 | 로컬 전용, 대화 내용 비접근 |
| 확장성 | 7 | 단일 사용자 |
| 운영 비용 | 6 | 로컬 실행이라 비용 거의 없음 |
| 유지보수성 | 3 | 예시 프로젝트로 읽히는 코드 |

## 3. 아키텍처 스타일 선호
- **기본 형태:** 단일 프로세스 모놀리스 — FastAPI 가 API 와 빌드된 Vue 정적 파일을 함께 서빙
- **통신 방식:** 조회는 REST, 실시간 갱신은 SSE
- **상태 관리:** 서버는 상태를 갖지 않는다. 진실의 원천은 `workspace/` 파일과 Claude Code 기록

## 4. 기술 선호 & 금지
| 구분 | 기술 | 이유 |
|------|------|------|
| 선호 | FastAPI, uvicorn, Vue 3, ECharts | 사용자 지정 스택, 시계열 차트에 강함 |
| 허용 | watchfiles (파일 변경 감지) | 폴링보다 반응이 빠를 때만 |
| 금지 | DB 서버, Docker 필수 구성, 외부 SaaS 로 데이터 전송 | 원칙 1·2 위반 |

## 5. 데이터 철학
- **일관성 모델:** 화면은 파일의 현재 값을 그대로 보여준다 (캐시는 수 초 이내 TTL)
- **데이터 소유권:** AI-DLC 파일은 Hook·오케스트레이터 소유, Claude 기록은 Claude Code 소유 — 대시보드는 읽기만. 예외는 제어 파일 하나
- **보존/삭제 정책:** 대시보드는 자체 데이터를 저장하지 않는다

## 6. 인프라 & 배포

- **환경 구성:** 로컬 단일 환경
- **IaC:** N/A
- **배포 전략:** 저장소를 내려받아 `run.bat` / `run.sh` 실행. 최초 실행 시 가상환경 생성과 패키지 설치 자동
