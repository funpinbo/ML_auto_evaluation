## 4. 발견 사항 (LTM 후보)
- 결정: D-15(가안) — ADR-004: Model/Dataset 재업로드(`POST /models`/`POST /datasets`)는 항상 신규 레코드(새 UUID)를 생성하고 매칭/UPDATE 로직은 두지 않는다. 기존 DDL(D-09, name/path UNIQUE 없음)이 이미 전제하던 동작을 공식 승인. `model_dataset_link` 복합 PK 는 "링크" 중복 차단만 유지(변경 없음). 근거: user/03 원칙1(과설계 금지)·원칙3(결과 비교 용이성=재현성 보존), 20§2 가중치(개발속도1위·유지보수성2위) — 매칭 키 정의·과거 Run 재현성 훼손 리스크가 있는 "갱신" 대안을 기각.
- 패턴: 없음(기존 패턴 재확인만)
- 이슈/리스크: I-02 해소(ADR-004로 확정). 신규 Task 후보 3건(§5) 발생 — product/backend·dba 가 각자 소유 파일에서 이 결정을 반영해야 리스크가 완전히 닫힘.
- 교훈: 이미 구현된 DDL(스키마)이 설계 결정을 사실상 선취하고 있을 때는, 새 정책을 "설계"하는 대신 기존 구현이 이미 전제하는 동작이 원칙에 부합하는지 먼저 검증하고 그대로 공식화하는 것이 가장 단순한 선택이다(원칙 1).
