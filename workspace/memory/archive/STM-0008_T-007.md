## 4. 발견 사항 (LTM 후보)
- 결정: ops 산출물은 charter 그대로 `workspace/project/ops/runbooks.md` 단일 문서로 통합(런북 + 로그 레벨 체크리스트), slo.md/알림/대시보드/용량계획은 작성하지 않음(N/A 명시, 03§7 근거).
- 패턴: -
- 이슈/리스크(신규, LTM 후보): 저장소 루트 `run.py` 가 이미 **AI-DLC Monitor**(이 저장소 자체 운영 도구, 포트 8765)용으로 구현·커밋되어 있는데, `20-architecture-analysis.md`§4/§6 와 `40-team-composition.md`§1 은 ML_miniops 의 실행 런처도 **같은 경로(`run.py`, backend 소유, 포트 8000 가정)**로 설계해 두었다. backend 가 설계대로 구현하면 기존 AI-DLC Monitor 런처를 덮어쓰게 된다. ops charter §10 의 QS-2 테스트 명령(`python run.py`)도 이 경로 충돌이 해소되지 않으면 그대로 실행할 수 없다. → §5 `[architecture]` Task 후보로 남김.
- 이슈/리스크(기존): 로그 레벨 규칙은 아직 backend 코드(`app/eval/engine.py`)가 없어 "검증"이 아니라 "구현 전 규칙 명시 + 구현 후 재확인 필요"임을 런북에 명시함. T-009 이후 backend 구현/qa 리뷰에서 실제 logging 호출이 이 매핑과 일치하는지 ops 가 재확인 필요.
- 교훈: 팀 charter·설계 문서가 이미 구체적 파일 경로(`run.py`)를 지정해 둬도, 그 경로에 **이미 다른 파일이 존재**하는지 실제로 확인해야 한다 — 이 저장소처럼 서로 무관한 프로젝트(ML_miniops / AI-DLC Monitor 프레임워크 자체)가 같은 루트를 공유하는 경우 설계 문서만 보고는 경로 충돌을 못 알아챈다.
