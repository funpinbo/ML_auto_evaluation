## 2. 로드한 컨텍스트
- NFR-003/QS-3: 서버가 127.0.0.1 등 로컬 주소에만 바인딩되는지 수동(코드 리뷰) 확인.
- LTM I-08(중요, 미해소): 저장소 루트 `run.py` 는 현재 **AI-DLC Monitor**(이 저장소 자체 운영 메타 도구, 포트 8765) 런처이고, ML_miniops 자체 실행 런처(20-architecture-analysis.md §4/§6: `uvicorn.run(host="127.0.0.1", port=8000)`, backend 소유)는 **아직 구현되지 않음**(T-033 미해결, backend 런처 구현 Task 자체도 tasks.md 에 명시적으로 없음).
- LTM I-10(T-008/STM-0009 에서 이미 발견): security 가 T-008 에서 저장소 루트 `run.py`·`monitor/backend/app/__main__.py`·`config.py` 를 코드 리뷰했지만 이는 AI-DLC Monitor 코드일 뿐 ML_miniops 와 무관 — "설계 문서 수준 PASS"로만 결론 내렸고, 실측 재검증은 `T-034`(deps: T-033, T-012, T-019, T-020)로 넘겨둠. **즉 T-019 자체가 이미 I-10 에서 예견된 상황** — ML_miniops 런처 코드가 없어 "코드 리뷰로 바인딩 주소 확인"이라는 DoD 를 문자 그대로 충족할 수 없다.
- security charter §10: 테스트 명령은 "코드 리뷰로 `uvicorn.run(..., host='127.0.0.1', ...)` 고정 여부 확인(수동)".
- deps T-002(architecture, 스캐폴드), T-008(security, threat-model/privacy) 모두 완료.
- 이번 Task 에서 확인할 것: (1) 정말 ML_miniops 런처 코드가 아직 없는지 재확인 (2) 있다면 바인딩 검증, 없다면 outcome 을 partial/blocked 중 어느 쪽으로 할지 — DoD 미충족 원인이 선행 Task(T-033, 런처 구현) 부재이므로 "이 Task 를 지금 완전히 끝낼 수 없다"는 점을 명확히 STM 에 기록.

## 3. 작업 로그
- run.py(저장소 루트) 재리뷰: `BIND_HOST = "127.0.0.1"` 상수 고정(L36), `--port`/`--no-browser` 외 호스트 변경 CLI 옵션 없음(L379-384) — 이 파일은 **AI-DLC Monitor**(포트 8765, `monitor/backend/app`) 런처임을 재확인(LTM I-08 그대로).
- `Glob`/`Grep` 으로 저장소 전체(`monitor/**` 제외)에서 `uvicorn` 참조 재검색: ML_miniops 쪽(`app/`)에는 `run.py`/`config.py`/`uvicorn.run` 호출이 **여전히 없음**. `app/` 하위에는 `app/__init__.py`, `app/api/__init__.py`, `app/eval/repository.py`, `app/web/__init__.py` 만 존재하고 `app/web/{static,templates}` 는 `.gitkeep` 뿐.
- `tasks.md` 확인: `T-033 [architecture] run.py 경로 충돌 해소` 아직 미착수(`[ ]`), ML_miniops 런처를 구현할 backend Task 는 여전히 tasks.md 에 생성돼 있지 않음(T-033 설명에 "미생성"으로만 언급). `T-012 [frontend] 업로드 화면 구현` 도 미착수.
- 결론: T-008(STM-0009) 시점과 비교해 상태 변화 없음 — DoD("run.py 코드 리뷰로 바인딩 주소 확인")의 대상인 ML_miniops 자체 런처 코드가 존재하지 않아 실측 코드 리뷰를 수행할 수 없다. `workspace/project/security/threat-model.md` §1.5 에 2026-10-27 재확인 결과를 추가 기록(동일 결론, T-034 로 실측 이전).

## 4. 발견 사항 (LTM 후보)
- 결정: T-019 는 "설계 문서 수준 PASS 유지, 실측은 코드 부재로 불가 — T-034 로 이전" 으로 재확인만 하고 종료한다. 더 할 수 있는 코드 리뷰가 없다(검증 대상 코드가 없기 때문).
- 패턴: 선행 Task(T-033 architecture, backend 런처 구현)가 완료되지 않은 채로 하류 보안 검증 Task(T-019)가 tasks.md 상 선행조건 없이 실행 가능하도록 되어 있으면, 매번 "코드 없음 → 재확인 불가"만 반복하게 된다. 이런 경우 해당 Task 의 `deps` 에 선행조건을 명시적으로 추가해야 중복 재확인을 막을 수 있다.
- 이슈/리스크: tasks.md 상 `T-019` 의 `deps` 가 `T-002, T-008` 뿐이라 `T-033`(실제 선행조건)이 명시돼 있지 않다 — 결과적으로 T-019 를 "지금" 실행해도 DoD 를 채울 수 없는데 계획상으론 실행 가능한 상태였다.
- 교훈: 보안 리뷰에서 "코드 리뷰로 확인"류 DoD 를 가진 Task 는 실행 전에 검증 대상 코드의 실존 여부를 먼저 확인해야 한다(이번에도 I-10 의 교훈이 그대로 재현됨).
