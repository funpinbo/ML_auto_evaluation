## 4. 발견 사항 (LTM 후보)
- 결정:
  - D-23(제안): `app/api/__init__.py`(backend 소유)를 frontend 가 직접 수정하지 않기 위해, `app/web/routes.py` 가 `from app.api import app` 로 공유 FastAPI 인스턴스를 import 한 뒤 모듈 로드 시점 부작용으로 `app.mount("/static", ...)`·`app.include_router(router)` 를 스스로 등록하는 "self-registration on import" 패턴을 채택. 의존 방향이 20§4 "webui --> api" edge 와 일치(frontend→backend 단방향 import, 역방향 없음). `app/web/__init__.py` 가 `from app.web import routes as routes` 로 패키지 import 만으로 등록이 트리거되게 함. 남은 조건: `app/__main__.py`(T-036, backend)가 `from app.api import app` 뒤에 `import app.web` 한 줄을 추가해야 실행 시 웹 UI 가 실제로 서빙됨(아래 Task 후보 참고).
  - requirements.txt 에 `jinja2==3.1.6`(+`MarkupSafe==3.0.4`) 추가 — D-19 선례(backend 가 fastapi/uvicorn 등을 직접 추가)와 동일하게 frontend 가 직접 추가(02§9 승인 불요).
- 패턴:
  - 업로드 화면 data-testid 네이밍 규칙(이 Task 에서 최초 확립, qa 미합의 — template 상단 주석에 기록): `<화면>-<역할>[-<상태>]` kebab-case. 예: `model-upload-form`/`model-upload-submit`/`model-upload-status`/`model-upload-error`, `model-list`/`model-list-empty`/`model-list-loading`/`model-list-error`/`model-list-item`, `r2-warning`. dataset-* 는 대칭 쌍. 다음 Task(T-014 연결 화면 등)도 이 규칙을 재사용.
  - 화면 상태 4종(기본/로딩/오류/빈)을 서버 렌더링 폴백(초기 HTML에 "빈 상태" 텍스트 포함) + 클라이언트 JS 전환(로딩 텍스트 → 목록/오류/빈 메시지로 치환)의 이중 구조로 구현 — JS 비활성/느린 네트워크에서도 최소한 빈 상태 메시지가 보이도록 함.
  - 422 에러 바디의 `detail` 이 문자열(도메인 에러)과 pydantic 검증 배열(`[{loc,msg,...}]`, 필수 필드 누락) 두 형태로 온다(02§6 "FastAPI 기본 HTTPException" 전제가 실제로는 pydantic 자동 422 에서는 다른 구조임) — 화면에서 `detail` 을 그대로 노출하려면 문자열/배열/객체를 모두 사람이 읽는 문장으로 변환하는 포매터가 필요(`upload.js::formatDetail`). 이후 다른 화면(T-014/T-016)도 동일 포매터 재사용 권장.
- 이슈/리스크:
  - `app/__main__.py`(T-036, ADR-005)가 아직 없어 `python -m app` 으로 실제 서버를 띄워 브라우저로 "/" 를 여는 것은 지금 당장 불가능 — 이번 Task 의 수동 확인은 (a) `TestClient` 통합 테스트(46 passed) + (b) 격리 cwd 에서 직접 `uvicorn.run(app.api.app, host="127.0.0.1", port=8099)` 로 임시 기동 후 curl 로 실제 HTTP round-trip(GET/POST, 성공/오류 양쪽) 확인으로 대체함. T-036 이 `import app.web` 을 포함해야 완전한 "브라우저로 열기"가 가능해짐.
  - 접근성/Core Web Vitals 자동 검사 도구는 두지 않음(design 팀 미생성, frontend charter §10) — 수동 점검만 수행: 폼 label/legend, `aria-live`, `role="alert"/"status"`, 포커스 아웃라인 CSS. Lighthouse 등 실측은 하지 않음(범위 밖, 명시).
- 교훈:
  - 다른 팀 소유 파일(`app/api/__init__.py`)을 "건드리지 않는다"는 제약은, 그 파일이 들고 있는 객체(FastAPI `app` 인스턴스)를 런타임에 import 해서 확장하는 것까지 막지는 않는다 — 설계 다이어그램(20§4)의 의존 방향이 이미 "frontend→backend" 로 명시돼 있다면, 파일 수정 없이 import 시점 부작용으로 통합하는 패턴이 소유권 경계와 실행 가능성을 동시에 만족시킨다.
  - TestClient 기반 통합 테스트만으로는 "실제 바이트가 네트워크 소켓을 거쳐 왕복하는지"(예: StaticFiles 마운트, 실제 멀티파트 바디 파싱)를 완전히 재현하지 못할 수 있어, 짧게라도 실제 `uvicorn` 프로세스를 띄워 `curl` 로 재확인하는 한 단계를 추가하면 "실행하지 않은 검증을 통과로 쓰지 않는다"(02§5)를 더 엄격히 지킬 수 있다.
