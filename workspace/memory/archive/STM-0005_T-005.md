## 4. 발견 사항 (LTM 후보)
- 결정: `dummy_regressor.py` 는 scikit-learn(LinearRegression)으로만 구현한다 — ADR-002 Decision #3(`framework` 은 메타데이터로만 보관, 평가 엔진이 분기하지 않음)에 따라 TC-002-02(`framework=pytorch` 로 업로드하는 테스트)에도 이 fixture 를 그대로 재사용할 수 있고, 실제 torch 설치가 필요 없다
- 패턴: 모델 fixture 는 별도 pickle 바이너리 없이, import 시점에 대응 CSV 와 **동일한 `random_state`/파라미터**로 합성 데이터를 재생성해 즉석 학습하는 방식으로 `predict(X)->y` 계약을 충족시킨다(ADR-002 "스크립트 안에서 즉석 학습" 허용 패턴) — fixture 와 CSV 가 항상 같은 분포를 쓰도록 유지보수 포인트를 스크립트 상단 주석에 명시
- 이슈/리스크: 현재 python 환경(및 저장소)에 pandas/numpy/scikit-learn 의존성이 전혀 선언되어 있지 않다(app/ 에 requirements.txt 없음). FR-002/FR-004 평가 엔진과 T-005 fixture 모두 pandas+scikit-learn 을 전제로 하므로(02§1 Data 행), 실제 pytest 실행(T-009 이후)을 위해서는 backend/cicd 가 `app` 전용 venv + requirements.txt(pandas, scikit-learn, 선택적 torch, pytest)를 마련해야 한다 — 미비 시 이후 모든 pytest 기반 리뷰가 "실행 불가"로 blocked 될 위험
- 교훈: 02§11 "전역(시스템) Python 환경에 설치 금지" 는 "검증을 생략하라"는 뜻이 아니다 — scratchpad 의 격리된 임시 venv 를 만들어 실제로 실행해보고, venv 자체는 저장소/영구 환경에 남기지 않는 방식으로 "실행하지 않은 검증을 통과로 쓰지 않는다"(02§5)를 지키면서도 시스템 환경을 건드리지 않을 수 있다
