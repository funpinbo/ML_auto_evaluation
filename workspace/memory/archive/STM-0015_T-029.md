## 2. 로드한 컨텍스트
- LTM I-03: `SCHEMA_DDL` 은 FK(`REFERENCES`)를 선언하지만, SQLite 는 연결마다 `PRAGMA foreign_keys = ON` 을 실행해야 FK 제약이 실제로 강제됨. 현재 `init_schema()`/운영 코드 어디에도 이 PRAGMA 설정이 없어 FK 제약이 조용히 무력화될 수 있음.
- LTM D-17(STM-0014, T-009 에서 이미 구현): `create_link`/`create_evaluation` 은 참조 대상 존재를 **애플리케이션 레벨**에서 먼저 검사해 `NotFoundError` 를 올리는 방식으로 FR-001 AC-5 를 PRAGMA 와 무관하게 1차 보장해둠 — T-029(DB 레벨 FK 강제)는 이것과 **상호 보완**이며 중복이 아니다. 즉 애플리케이션 레벨 검사를 지우거나 대체하면 안 되고, 그 아래 DB 레벨에서도 거부되도록 PRAGMA 를 추가하는 것이 이번 Task.
- `get_connection(db_path=DEFAULT_DB_PATH)` (T-009 구현): `:memory:` 지원, 파일 경로일 때 상위 디렉토리 생성 + `init_schema` 자동 실행 — 이 함수가 PRAGMA 를 설정할 자연스러운 지점.
- backend charter §10: 테스트 명령 `pytest`(선택), 핵심 로직 더미 데이터 단위 테스트, lint: `ruff format`/`ruff check`.
- deps: T-009(완료).

## 3. 작업 로그
- `app/eval/repository.py` `get_connection()` 에서 `sqlite3.connect()` 직후, `init_schema()` 호출 전에
  `conn.execute("PRAGMA foreign_keys = ON")` 추가 — `:memory:`/파일 경로 모두 이 함수 하나를 거치므로
  커넥션을 열 때마다(재연결 포함) 매번 재설정됨.
- `tests/test_repository.py` 에 FK 강제 검증 테스트 6건 추가:
  - `test_get_connection_enables_foreign_keys_pragma`: `PRAGMA foreign_keys` 조회 결과가 1인지 확인.
  - `test_foreign_keys_pragma_rejects_raw_link_insert_with_missing_model/dataset`: `repo.create_link`
    의 애플리케이션 레벨 사전 검사(NotFoundError, D-17)를 **우회**해 `model_dataset_link` 에 raw SQL
    INSERT 를 직접 시도 → DB 레벨 FK 제약으로 `sqlite3.IntegrityError`("FOREIGN KEY constraint failed")
    발생 확인.
  - `test_foreign_keys_pragma_rejects_raw_evaluation_insert_with_missing_run/model/dataset`: 동일한
    방식으로 `evaluation` 테이블의 run_id/model_id/dataset_id FK 3개를 각각 raw INSERT 로 위반 시도 →
    모두 거부됨을 확인.
- `.venv/`(gitignore 처리됨, 커밋 대상 아님)를 저장소 루트에 새로 만들고 `requirements.txt`(cicd 고정,
  T-030) 로 pandas/scikit-learn/pytest/ruff 설치 — 이 환경이 없으면 `python -m pytest`/`ruff` 가
  "No module named pytest" 로 즉시 실패해 검증 자체가 불가능했음(이전 Task 들이 이미 이 절차를 전제).
- 검증 명령 실행 결과 (모두 `.venv/Scripts/python.exe` 사용):
  - `pytest tests -v` → 26 passed (기존 20건 + 신규 6건 모두 PASS).
  - `ruff format --check app tests` → 최초 1건(`tests/test_repository.py`) unformatted 발견 →
    `ruff format app tests` 로 자동 정렬 → 재실행 시 9 files already formatted.
  - `ruff check app tests` → All checks passed.

## 4. 발견 사항 (LTM 후보)
- 결정: `get_connection()` 을 PRAGMA 설정 지점으로 확정(STM §2 에서 이미 식별한 자연스러운 지점) — 커넥션을
  직접 `sqlite3.connect()` 로 여는 다른 경로가 코드베이스에 없음(repository.py 가 유일한 연결 생성 지점)을
  확인했으므로 이 한 곳의 수정으로 "커넥션 오픈마다" 요구사항을 충족함.
- 패턴: DB 레벨 FK 강제를 테스트할 때는 `repo.create_link`/`create_evaluation` 같은 애플리케이션 레벨
  사전 검사(NotFoundError)를 거치지 않고 `conn.execute(...)` 로 raw SQL INSERT 를 직접 호출해야 PRAGMA
  자체의 효과를 분리해서 검증할 수 있다 — 상위 함수를 그대로 호출하면 NotFoundError 가 먼저 발생해
  PRAGMA 가 실제로 동작하는지 확인할 수 없음.
- 이슈/리스크: 로컬 `.venv/` 가 저장소에 없으면(신규 체크아웃/새 세션마다) pytest/ruff 실행이 즉시
  막힌다 — 이번에 매번 재생성함. requirements.txt 주석(T-030)에 이미 절차가 문서화되어 있어 agent가
  그대로 따르면 되지만, 매 세션마다 설치 시간(수 분)이 소요됨.
