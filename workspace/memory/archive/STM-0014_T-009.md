## 4. 발견 사항 (LTM 후보)
- 결정:
  - Repository 함수는 model_id/dataset_id 를 호출자가 넘기지 않고 내부에서 `uuid.uuid4()` 로 발급한다(ID 생성 로직을 API 라우터마다 중복시키지 않기 위함) — T-010/T-011/T-013/T-015 구현 시 이 계약을 그대로 따를 것.
  - FR-001 AC-5(미업로드 model_id/dataset_id 로 연결 시도 시 4xx)를 SQLite `PRAGMA foreign_keys` 설정(T-029, I-03, 아직 미적용) 여부와 무관하게 보장하기 위해, `create_link`/`create_evaluation` 이 참조 대상 존재 여부를 애플리케이션 레벨에서 먼저 검사하고 `NotFoundError` 를 올리는 방식으로 구현함. T-029 가 PRAGMA 를 추가해도 이 검사와 충돌하지 않음(이중 방어).
  - 동일 (model_id, dataset_id) Link 중복 생성 시도는 `model_dataset_link` 복합 PK 로 `sqlite3.IntegrityError` 가 그대로 전파되도록 두었다 — FR-001 story 의 "중복 연결 허용 여부 미정" Out of scope 를 backend 가 임의로 결정(흡수/무시)하지 않기 위함. API 라우터(T-013)가 이 예외를 어떻게 4xx 로 매핑할지는 별도 결정 필요.
- 패턴:
  - 같은 임시 격리 venv 생성→설치→실행→검증→완전 삭제→`git status --short` 로 잔존 재확인 패턴(STM-0005~0007)을 T-009 에도 그대로 적용함.
- 이슈/리스크:
  - I-07/T-032(`app/eval/repository.py` ruff format 미통과)는 이번 Task 에서 `ruff format app tests` 실행으로 부작용 해소됨 — T-032 는 별도로 수행할 필요 없음(오케스트레이터가 tasks.md 에서 해소 처리 검토).
  - I-03(T-029, `PRAGMA foreign_keys = ON`)은 여전히 열려 있음 — 이번 Task 의 애플리케이션 레벨 `NotFoundError` 검사는 FK 누락을 보완하지만, DB 레벨 강제(T-029)는 별개로 남아 있음(중복 작업 아님, 상호 보완).
