# P1 UAT 체크리스트 (KPI-01 · KPI-02 · FR-005 리허설 · A11 확인)

> 수행: product(진행·기록) + PO funpinbo(판정). 시점: T-014 (T-013 통과 후, M1 2026-11-06 전).
> 모든 측정은 사람이 직접 하고 결과는 §6 표에 기록한다. 실행하지 않은 항목은 `미실행` 으로 남기고 PASS 로 쓰지 않는다.
> 실제 `~/.claude` 기록은 테스트 자동화에 쓰지 않는다(02 §5). UAT 는 사용자 본인 PC 의 실제 사용이므로 예외이며, 화면 캡처를 남길 때는 대화 내용·경로가 보이지 않게 한다.

## 0. 공통 준비
- [ ] U0-1 `main` 의 P1 결과물로 실행한다. 커밋 해시를 §6 에 기록한다.
- [ ] U0-2 브라우저 창 크기(px)와 OS 화면 배율을 기록한다. "첫 화면" = 이 창에서 **스크롤·클릭 없이** 보이는 영역.
- [ ] U0-3 스톱워치(초 단위 이상 정밀도)를 준비한다. 질문은 진행자가 읽고, 응답자는 화면만 보고 답한다.
- [ ] U0-4 정답은 측정 직전에 **파일에서 직접** 확인해 적어 둔다(`workspace/memory/short-term.md`, `tasks.md`, `.monitor/claude-status.json`). `aidlc.py status` 는 closed STM 을 아카이브하는 부작용이 있으므로 정답 확인용으로 쓰지 않는다(D-07).

## 1. KPI-01 — 현재 상태 파악 5초 이내 (00 A12 고정 질문 3개)
### 1.1 상태 준비
- [ ] K1-0 `/aidlc-run 3` 이 실행 중이고 STM 이 `active`(Task·팀 있음)인 상태를 만든다.
- [ ] K1-0b statusLine 스냅샷에 `rate_limits` 가 있는 상태(Pro/Max, CLI 세션에서 1회 이상 응답 후)를 만든다. 없으면 "한도 정보 없음" 안내가 보이는지로 Q3 를 판정한다(§1.3 변형).

### 1.2 절차
1. 브라우저에서 대시보드 URL 을 연다.
2. 모든 Must 패널이 값 또는 "데우는 중" 을 표시한 순간 = **첫 화면 로딩 완료**. 여기서 스톱워치를 시작하지 않는다.
3. 진행자가 질문을 읽기 시작하는 순간 스톱워치 시작, 응답자가 답을 말하는 순간 정지. 질문마다 따로 측정.
4. 응답자는 스크롤·클릭·탭 전환·터미널·파일 열기를 하지 않는다. 하면 그 질문은 FAIL.

| ID | 고정 질문 (A12) | 정답 출처 (화면) | 통과 기준 |
|----|----------------|------------------|-----------|
| K1-Q1 | "지금 몇 단계인가?" | FR-001 현재 단계(번호·이름·상태) | 정답과 일치 **and** ≤ 5.0 초 |
| K1-Q2 | "지금 어떤 Task 를 어느 팀이 하고 있나?" | FR-003 현재 Task ID·팀 | Task ID·팀 모두 일치 **and** ≤ 5.0 초 |
| K1-Q3 | "5시간 한도를 몇 % 썼고 언제 초기화되나?" | FR-004 5시간 % · 초기화 시각 | % 는 화면 값(정수)과 스냅샷 값의 반올림 일치, 초기화 시각 일치 **and** ≤ 5.0 초 |

### 1.3 변형 (선택, 기록 권장)
- K1-Q3' 스냅샷 `rate_limits` 없음: 응답 "한도 정보 없음" 이 5초 이내면 PASS (10 §6 기준 6 의 사람 확인).
- K1-R 반복: 서로 다른 상태(예: 다른 Task 진행 중)에서 한 번 더 측정.

### 1.4 판정
- **KPI-01 PASS** = K1-Q1·K1-Q2·K1-Q3 가 모두 PASS(정답 + 각 ≤ 5초 + 첫 화면만).
- 하나라도 FAIL 이면 원인(배치·문구·로딩)을 §6 비고에 적고 `[frontend]`/`[product]` Task 후보로 STM §5 에 남긴다.

## 3. KPI-02 — 깨끗한 PC 설치 리허설 (실행 동작 1번, 5분 이내)
### 3.1 "깨끗한 PC" 조건 (각 항목 확인 후 기록)
- [ ] Python 3.11 이상 설치됨(01 §7 전제). 버전 기록.
- [ ] 이 저장소를 처음 받음 — `monitor/.venv`·해시 마커 없음.
- [ ] Node/npm 없음(있으면 기록하고 PATH 에서 빼고 진행 권장).
- [ ] 인터넷 연결됨(pip 설치용). 회선 종류를 기록.
- [ ] 다운로드·압축 해제 시간은 KPI 에 넣지 않는다(01 "다운로드 후"). 따로 기록.

### 3.2 절차
| ID | OS | 단일 실행 동작 | 타이머 시작 | 타이머 정지 |
|----|----|----------------|-------------|-------------|
| K2-W | Windows 10/11 1대 | 탐색기에서 `run.bat` 더블클릭 | 더블클릭 순간 | 자동으로 열린 브라우저에 FR-001·003·004 상단 행이 보이는 순간 |
| K2-U | macOS 또는 Linux 1대 | 터미널에서 `./run.sh` 1회 (또는 `python3 run.py`) | Enter 순간 | 같음 |

- 실행 중 사용자는 아무 입력도 하지 않는다(프롬프트 응답·주소 입력·추가 명령 = 동작 추가 → FAIL).
- 이어서 서버를 끄고(Ctrl+C) 같은 동작으로 재실행해 `설치 생략` 과 소요 시간을 기록한다(SCOPE-01 AC-5, 기록만).

### 3.3 판정
- **K2-W / K2-U 각각 PASS** = 실행 동작 1번 **and** 브라우저 자동 열림 **and** 첫 화면까지 ≤ 5:00.
- **KPI-02 PASS** = K2-W PASS **and** K2-U PASS (10 §6 기준 2: Windows 1 + macOS/Linux 1).

## 4. FR-005 일시정지/재개 리허설 (10 §6 기준 3)
> 실제 VSCode + Claude Code 세션에서 수행한다. 각 단계에서 대시보드 제어 패널 문구(FR-005 §2.1)와 메모리 패널(FR-003)을 함께 본다.

### R-1 기본 흐름 (`/aidlc-run 3`)
- [ ] R1-1 `/aidlc-run 3` 실행 → 제어 패널 `실행 중` 0/3.
- [ ] R1-2 첫 사이클의 팀 Agent 작업 중에 **일시정지** 클릭 → 5초 이내 `일시정지 요청됨 (현재 Task 진행 중)`.
- [ ] R1-3 현재 Task 가 끝까지 진행되는지 확인: STM 닫힘 → cascade 1/3·2/3(필요 시 3/3) 처리 완료 → 다음 Task 의 STM 이 열리지 않음.
- [ ] R1-4 5초 이내 `일시정지됨 (세션 대기 중)` + 남은 허용 시간(약 2시간). 메모리 패널: STM `idle`, 미처리 cascade "없음". 진행 1/3.
- [ ] R1-5 VSCode 채팅에 "일시정지됨 — 대시보드에서 재개" 한 줄 보고만 있고, 대기 반복 호출마다 긴 설명이 없다.
- [ ] R1-6 몇 분 뒤 **재개** 클릭 → 5초 이내 `실행 중`, `/aidlc-run` 재입력 없이 2번째 Task 시작.
- [ ] R1-7 루프가 3/3 까지 진행 후 종료 → `루프 없음` + `완료 — 3회 반복을 모두 마쳤습니다`. 실행 사이클 정확히 3회.
- [ ] R1-8 수동 복구 작업(STM 수정·cascade 수동 처리·명령 재입력) 0건.
- 선택: R1-9 cascade 처리 중(4~7단계)에 일시정지를 눌러 R1-3~R1-4 와 같은 결과인지 확인(FR-005 AC-6).

### R-2 대기 중 세션 사라짐 (FR-005 AC-16)
- [ ] R2-1 `/aidlc-run 2` → 일시정지 → `일시정지됨` 확인.
- [ ] R2-2 VSCode 창(세션)을 닫는다. 시각 기록.
- [ ] R2-3 2분 5초 이내 `세션 없음` + "`/aidlc-run 1` 로 다시 실행하세요"(남은 수) 안내. 걸린 시간 기록.

### R-3 일시정지 상한 초과 (기본 2시간, FR-005 AC-13)
- [ ] R3-1 `/aidlc-run 2` → 일시정지(본문 기본값, 7200 s) → `일시정지됨` 확인, 시작 시각 기록.
- [ ] R3-2 재개하지 않고 2시간 + 수 분 대기. 대기 중 heartbeat 가 유지되어 `세션 없음` 으로 바뀌지 않는지 중간 확인(30분 간격 권장).
- [ ] R3-3 상한 초과 후: 세션이 루프를 정상 종료 보고(남은 반복 수 안내), 대시보드 `루프 없음` + `일시정지 상한(2시간) 초과로 종료 — 남은 반복 1회: /aidlc-run 1`.
- [ ] R3-4 STM 이 일시정지 시점과 같다(내용 변경 없음, `idle` 유지), 미처리 cascade 없음.
- [ ] R3-5 대기 반복 호출 횟수와 그동안의 토큰 사용량(사용량 패널)을 기록한다(10 §7 최상위 1 검증, 참고값).
- 보조(선택, R-3 을 대체하지 않음): `max_pause_sec: 600` 으로 10분 상한 리허설.

### 판정
- **FR-005 리허설 PASS** = R-1 전 항목 + R-2 + R-3 PASS. R-1 실패는 MVP 기준 3 FAIL.
- R-01 스파이크 실패로 후퇴안(일시정지 = 루프 종료)이 적용된 경우 R1-6 은 01 §10 결정과 다르므로 FAIL 로 기록하고 PO 결정을 받는다.
