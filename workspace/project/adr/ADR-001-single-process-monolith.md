# ADR-001: 아키텍처 스타일 — 단일 프로세스 모놀리스 선택

## Context
- ML_miniops 는 1인 사용자가 로컬 PC(localhost) 에서 "하루" 안에 완성해야 하는 ML 모델 평가 도구다(00§1, 01).
- user/03-architecture-philosophy.md §1 원칙 1("단순함 우선")·2("로컬 단일 프로세스")가 최우선 원칙이며, §2 품질속성 순위는 개발속도(1위)·유지보수성(2위)가 가용성/신뢰성(3위)·확장성(4위)·성능(5위)보다 압도적으로 높다.
- §4 "금지 기술"에 클라우드 매니지드 서비스와 별도 메시지 브로커/분산 시스템이 명시되어 있다.
- 동시 사용자 1명(NFR-004), 성능 목표 없음(NFR-001), 상시 가동 불필요·재시작으로 복구 충분(NFR-002) 전제가 있다.

## Decision
**단일 FastAPI 프로세스** 안에서 API 라우터·모델 로더·평가 실행기·지표 계산기·시각화 생성기·데이터 접근 계층을 모두 실행하고, 상태는 SQLite 파일에 저장한다. 통신은 동기 REST 만 사용하며, 별도 워커 프로세스/메시지 브로커/비동기 작업 큐를 두지 않는다. (20-architecture-analysis.md §2·§3 가중합계 비교에서 최고점.)

## Alternatives
| 대안 | 설명 | 기각 이유 |
|------|------|-----------|
| B. 모놀리스 + 평가 전용 자식 프로세스 | 웹 서버는 유지하되 `predict()` 실행만 `subprocess` 로 격리 | 가용성 점수는 소폭 높지만(§2), IPC/프로세스 생명주기 관리 구현 비용이 "하루" 일정(원칙 1)과 충돌. SQLite 영속화만으로 QS-2(재시작 복구) 요구를 충족해 과설계(원칙 1 안티패턴, §10)로 판단 |
| C. 모놀리스 + 메시지 브로커 기반 비동기 작업 큐(Celery/Redis) | Run 실행을 비동기 워커에 위임 | 03§4 "별도 메시지 브로커/분산 시스템" 금지 목록에 **직접 해당** — 점수와 무관하게 원칙 위반으로 제외 |

## Consequences
- **긍정**: 프로세스 경계·IPC·브로커가 없어 구현·디버깅이 가장 단순(개발속도·유지보수성 1·2위 충족). 배포도 `python run.py` 한 줄로 충분(03§6).
- **부정/트레이드오프**: 모델 `predict()` 실행 중 크래시가 웹 서버 프로세스 전체에 영향을 줄 수 있음. 이는 업로드 시점 contract 검증(ADR-002, fail fast)과 SQLite 영속화 후 재시작 복구(QS-2)로 완화하며, 완전한 격리는 하지 않기로 의도적으로 수용한다.
- 확장성(4위)·성능(5위) 손실은 03§2 순위상 손실로 간주하지 않는다(01 NFR-001/004 전제와 일치).
