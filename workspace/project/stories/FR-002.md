# FR-002. 모델·데이터 입력 기능

## 사용자 스토리
사용자로서 PyTorch 또는 scikit-learn 모델 스크립트와 CSV 데이터 파일을 웹에서 직접 업로드하고 싶다, 왜냐하면 Jupyter 밖에서도 평가를 돌릴 수 있어야 하기 때문이다. (01§5 원문)

## 전역 계약 (수용 기준의 근거 — architecture/D-02 확정 사항, product 는 임의로 바꾸지 않음)
- 모델 스크립트는 모듈 전역 함수 `predict(X) -> y` 를 노출해야 한다(ADR-002). 프레임워크(PyTorch/scikit-learn) 분기는 평가 엔진에 없다.
- CSV 는 "마지막 컬럼 = 라벨" 컨벤션이 고정이다(ADR-002§3). 열 수는 2개 이상이어야 한다(20§9 R6).
- 모델 업로드 시 `problem_type`(classification|regression)을 사용자가 직접 지정한다(추론 아님, D-03/ADR-003).

## 화면 흐름 (10§4 사용자 여정 1단계)
1. 업로드 화면에 "모델 업로드" 폼(파일 선택 + name + framework + problem_type 라디오)과 "데이터 업로드" 폼(파일 선택 + name)이 있다.
2. 모델 업로드 제출 시 서버가 즉시 `predict` 계약을 검증(import + hasattr)하고, 통과하면 업로드 목록에 모델이 나타난다. 실패하면 화면에 오류 메시지가 뜨고 목록에 추가되지 않는다(fail fast, QS-6).
3. 데이터 업로드 제출 시 서버가 CSV 파싱 가능 여부와 열 수(≥2)를 검증하고, 통과하면 업로드 목록에 데이터셋이 나타난다.
4. 업로드된 모델/데이터 목록이 이후 FR-001(연결) 화면에서 선택 가능한 대상으로 그대로 이어진다.

## API 계약 참조 (20§5)
- `POST /models` {file, name, framework, problem_type} → 201 {model_id} (predict 계약 위반 시 4xx)
- `POST /datasets` {file, name} → 201 {dataset_id} (CSV 파싱 실패/열 수 <2 시 4xx)

## 수용 기준 (Given/When/Then)

### AC-1 (모델 업로드 성공 — 기본 흐름, 01§5 원문 수용 기준)
Given `predict(X) -> y` 를 노출하는 scikit-learn 모델 스크립트 1개, framework="sklearn", problem_type="classification",
When 사용자가 웹 UI 로 업로드,
Then 시스템이 모델을 평가 대상 목록에 등록하고(model_id 발급), 업로드 화면 목록에 나타난다.

### AC-2 (모델 업로드 성공 — PyTorch)
Given `predict(X) -> y` 를 노출하는 PyTorch 모델 스크립트 1개, framework="pytorch", problem_type="regression",
When 사용자가 웹 UI 로 업로드,
Then 시스템이 모델을 평가 대상 목록에 등록한다. (10-business-analysis §0.1 결론: 평가 엔진은 프레임워크별 분기 로직을 갖지 않으므로 PyTorch/sklearn 업로드 처리 결과가 동일한 구조로 등록됨)

### AC-3 (데이터 업로드 성공)
Given 열이 3개 이상이고 마지막 컬럼이 라벨인 CSV 파일 1개,
When 사용자가 웹 UI 로 업로드,
Then 시스템이 데이터셋을 평가 대상 목록에 등록하고(dataset_id 발급), 업로드 화면 목록에 나타난다.

### AC-4 (예외 — predict 계약 위반, QS-6 fail fast)
Given `predict` 함수가 없는(또는 다른 이름의) 모델 스크립트,
When 사용자가 웹 UI 로 업로드,
Then 시스템은 모델을 등록하지 않고 4xx 오류를 반환하며, 오류 메시지에 `predict(X) -> y` 계약을 명시한다. 콘솔에 ERROR 로그가 남는다(user/02§7).

### AC-5 (예외 — CSV 파싱 실패/열 부족)
Given CSV 로 파싱되지 않는 파일(또는 열이 1개뿐인 CSV),
When 사용자가 웹 UI 로 업로드,
Then 시스템은 데이터셋을 등록하지 않고 4xx 오류를 반환한다.

### AC-6 (problem_type 필수 입력)
Given 모델 업로드 폼에서 problem_type(classification/regression)을 선택하지 않은 상태,
When 사용자가 제출,
Then 서버가 pydantic 검증으로 4xx 를 반환한다(필수 필드 누락, user/02§8).

## MVP 성공 판단 기준과의 연결 (10§6)
"Given 모델 2개 이상 + 데이터셋 1개 이상 업로드"의 전제 단계. AC-1/AC-2 를 각 1회씩 수행하면 "모델 2개 업로드" 전제가 충족된다.

## Out of scope (본 스토리에서 하지 않음)
- 업로드 파일 바이러스/악성코드 검사, 샌드박싱(20§9 R2 — "본인이 작성/신뢰하는 스크립트만 업로드" 전제, 과설계 금지로 명시 제외)
- 동일 (model, dataset) 재업로드 시 신규/갱신 정책 — LTM I-02 미해결, **[architecture] Task 후보로 STM §5 에 기록.**
- problem_type 자동 추론 — D-03 에서 이미 "사용자 직접 지정"으로 확정, 추론 기능은 범위 밖
