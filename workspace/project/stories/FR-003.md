# FR-003. 평가 지표 선택 기능

## 사용자 스토리
사용자로서 Accuracy/F1/RMSE 중에서 평가에 쓸 지표를 직접 선택하고 싶다, 왜냐하면 모델마다 보고 싶은 지표가 다르기 때문이다. (01§5 원문)

## Phase 별 범위 (plan/tasks.md 확정 사항 — product 가 임의로 바꾸지 않고 그대로 수용 기준에 반영)
- **P1:** Accuracy/F1/RMSE 3종 모두 선택 UI 에 노출되고 전부 선택 가능하다(비활성화 없음, T-016). 호환성 필터는 "pass-through"로, problem_type 과 무관하게 선택한 지표로 평가를 시도한다. 계산 중 예외가 나면 해당 Evaluation 은 `status=error`(T-015).
- **P2:** 선택된 Model(들)의 `problem_type` 에 따라 비호환 지표는 UI 에서 비활성화되고(T-022), 백엔드 Compatibility Filter 가 사전 차단해 `status=skipped_incompatible`(T-021, ADR-003)로 기록한다.
- `METRIC_COMPATIBILITY`(30§5.2): classification→{accuracy, f1}, regression→{rmse}.

## 화면 흐름 (10§4 사용자 여정 3단계)
1. 연결 화면(FR-001)에서 등록된 Link(조합)마다, 또는 Run 실행 전 공통으로, Accuracy/F1/RMSE 체크박스가 보인다(구현 방식은 frontend 재량 — 조합별 선택 vs Run 전체 공통 선택 중 택1, 단 사용자에게 "이 Run 에 어떤 지표가 적용되는지"가 명확해야 함).
2. 사용자가 1개 이상의 지표를 선택한다. P1 에서는 선택 가능한 지표가 problem_type 과 무관하게 항상 3개 모두다.
3. 선택한 지표는 별도 제출 없이 Run 요청(FR-004)의 payload 일부로 함께 전송된다(20§5 — 지표 선택 전용 엔드포인트 없음).

## API 계약 참조 (20§5)
- 별도 엔드포인트 없음. `POST /runs` {combinations: [{model_id, dataset_id, metrics:[...]}]} 의 `metrics` 배열이 본 FR 의 결과물.

## 수용 기준 (Given/When/Then)

### AC-1 (P1 — 기본 흐름, 01§5 원문 수용 기준)
Given 등록된 Model-Dataset 조합(Link) 1건,
When 사용자가 Accuracy 를 선택하고 Run 을 실행(FR-004),
Then Accuracy 로 평가가 수행되고 Evaluation.value 가 저장된다(`status=success`, 계산 가능한 경우).

### AC-2 (P1 — 복수 지표 선택)
Given 등록된 Link 1건,
When 사용자가 Accuracy, F1 2개를 선택하고 Run 을 실행,
Then 해당 Link 에 대해 Evaluation 레코드가 지표별로 1건씩(총 2건) 생성된다.

### AC-3 (P1 — 지표 전체 노출, 필터링 없음)
Given problem_type="regression" 인 Model 로 구성된 Link,
When 사용자가 지표 선택 화면을 연다,
Then Accuracy/F1/RMSE 3개 모두 선택 가능한 상태로 보인다(비활성화된 항목 없음) — P1 에서는 problem_type 기반 UI 필터링을 하지 않는다.

### AC-4 (P1 — 비호환 지표 선택 시 pass-through, error 처리)
Given problem_type="regression" 인 Model 로 구성된 Link,
When 사용자가 Accuracy(비호환 지표)를 선택하고 Run 을 실행,
Then 시스템은 호환성 사전 차단 없이 계산을 시도하고, 계산이 실패하면 해당 Evaluation 은 `status=error`, `value=NULL` 로 저장되며 콘솔에 ERROR 로그가 남는다(P1 범위, T-015).

### AC-5 (P2 — 호환성 필터 활성화 후, T-021/T-022 완료 시점 기준)
Given problem_type="regression" 인 Model 로 구성된 Link,
When 사용자가 지표 선택 화면을 연다(P2 반영 후),
Then Accuracy/F1 은 비활성화되어 선택할 수 없고 RMSE 만 선택 가능하다. 그럼에도 비호환 조합이 Run 에 포함되면 Evaluation 은 `status=skipped_incompatible`, `value=NULL` 로 저장되고 WARN 로그가 남는다(ADR-003, 혼합 선택 시 합집합 노출 — 30§5.2).

### AC-6 (지표 미선택)
Given 등록된 Link 1건,
When 사용자가 지표를 1개도 선택하지 않고 Run 을 시도,
Then Run 이 생성되지 않거나(4xx) 해당 Link 에 대한 Evaluation 이 생성되지 않는다 — 최소 1개 지표 선택이 Run 실행의 전제임을 UI 가 안내한다.

## KPI 연결
KPI-02(완료 모델 수/입력 모델 수) 는 FR-004 Run 실행 결과로 집계되며, 본 FR 에서 선택한 지표·Evaluation.status 가 그 집계의 입력이다. 자세한 해석은 FR-004 story 참고.

## Out of scope (본 스토리에서 하지 않음)
- 지표 추가(예: Precision/Recall/AUC) — 01§5 가 Accuracy/F1/RMSE 3종으로 확정(00§3.2 Q2), 범위 확장 없음
- P1 에서 호환성 사전 차단 UI — 명시적으로 P2 로 이관됨(위 Phase 표)

## Phase
P1: 선택 UI(필터 없음) + pass-through 평가. P2: 호환성 필터 활성화(T-021/T-022). 10§6 Fallback 적용 시에도 FR-003 최소 기능(지표 선택 가능)은 유지, 고도화(P2)만 후순위.
