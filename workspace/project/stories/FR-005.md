# FR-005. 결과 시각화

## 사용자 스토리
사용자로서 평가 결과를 그래프로 한눈에 비교하고 싶다, 왜냐하면 어떤 모델이 더 나은지 숫자보다 그래프로 보는 게 더 직관적이기 때문이다. (01§5 원문)

## Phase 별 범위 (10§5 근거 — 비교 그래프는 노력 낮아 P1, 상관관계는 Q9 리스크 발생 시 가장 먼저 줄일 수 있는 범위로 P2)
- **P1:** 지표별 모델 비교 그래프(예: 모델별 지표 막대 그래프). pandas 로 Evaluation 을 집계해 생성(matplotlib Agg → PNG → base64 임베드, 20§7).
- **P2:** 지표 간 상관관계 그래프 추가.
- **10§6 Fallback 적용 시:** 그래프 없이 raw 표(Evaluation 레코드 나열)만으로도 임시 인정하되, 시간이 허락하면 FR-005 그래프를 순서대로 추가.

## 화면 흐름 (10§4 사용자 여정 5단계)
1. Run 완료(FR-004) 후 결과 화면으로 이동(또는 링크 클릭)하면, 해당 Run 의 Evaluation 결과가 표/그래프로 보인다.
2. P1: 지표별로 모델을 X축(또는 범례)으로 하는 비교 그래프가 1개 이상 보인다. `status=success` 인 레코드만 수치로 그려지고, `status=error`/`skipped_incompatible` 레코드는 그래프에서 제외하거나 별도 표기한다(20-architecture §9 R6 연계 과제를 product 가 "별도 표기 또는 제외, 수치 왜곡 없이"로 명확화).
3. P2: 같은 화면(또는 탭)에 지표 간 상관관계 그래프가 추가로 보인다.
4. 그래프 아래/옆에 raw 표(모델명, 데이터셋명, 지표, 값, 상태)도 함께 제공해 그래프로 판단하기 애매한 값은 표로 재확인할 수 있다.

## API 계약 참조 (20§5)
- `GET /runs/{run_id}/results` → HTML(그래프 임베드) 또는 JSON(차트 데이터)

## 수용 기준 (Given/When/Then)

### AC-1 (기본 흐름 — 01§5 원문 수용 기준, MVP 성공 판단 기준의 마지막 단계)
Given 완료된 평가 결과(Evaluation, 최소 1건 이상 `status=success`),
When 사용자가 결과 화면을 열면,
Then 지표별 모델 비교 그래프(예: 모델별 F1 막대 그래프)가 pandas 기반으로 렌더링된다.

### AC-2 (복수 모델 비교)
Given 같은 Run 안에 Model A, Model B 각각의 Accuracy Evaluation(`status=success`, 값 0.8/0.9)이 있는 상태,
When 사용자가 결과 화면을 열면,
Then 두 모델의 Accuracy 값이 하나의 그래프에서 비교 가능한 형태(예: 막대 2개)로 보인다.

### AC-3 (success 아닌 레코드 처리)
Given 같은 Run 안에 `status=success` Evaluation 1건과 `status=error`(또는 P2 의 skipped_incompatible) Evaluation 1건이 있는 상태,
When 사용자가 결과 화면을 열면,
Then success 레코드만 그래프 수치에 반영되고, error/skipped 레코드는 raw 표에 상태값과 함께 표시되어 "평가 안 됨"이 그래프 수치로 둔갑하지 않는다(값=NULL 그대로 노출, 0 으로 대체하지 않음).

### AC-4 (결과 없음 — 예외)
Given 아직 Run 을 한 번도 실행하지 않은 상태,
When 사용자가 결과 화면 URL(`GET /runs/{id}/results`)에 존재하지 않는 run_id 로 접근,
Then 404 오류 또는 "결과 없음" 안내가 표시되고, 빈 그래프로 오동작하지 않는다.

### AC-5 (P2 — 상관관계 그래프)
Given 같은 Run 안에 Model 들의 Accuracy, F1 두 지표가 모두 `status=success` 로 저장된 상태,
When 사용자가 결과 화면을 열면(P2 반영 후),
Then 지표 간 상관관계 그래프가 비교 그래프와 함께 추가로 렌더링된다.

### AC-6 (Fallback raw 표 — 10§6 일정 리스크 완화안 적용 시에만)
Given 10§6 Fallback 적용이 결정된 상태(FR-005 그래프가 아직 구현되지 않음),
When 사용자가 결과 화면을 열면,
Then 그래프 대신 raw 표(모델/데이터셋/지표/값/상태)가 최소한으로 제공되어 "결과 비교 자체는 가능"한 상태를 유지한다. 이 경우도 FR-005 의 Must 지정은 유지되며, 그래프는 후속 Task 로 추가된다(01§5 Must 변경 아님, Task 순서만 조정).

## MVP 성공 판단 기준과의 연결 (10§6)
"...결과 화면에 지표 비교 그래프" 가 본 FR 의 AC-1/AC-2 로 검증된다. KPI-02 해석은 FR-004 story 참고(본 FR 은 시각화만 다룸, KPI 산식 자체를 재정의하지 않음).

## Out of scope (본 스토리에서 하지 않음)
- 클라이언트 JS 차트 라이브러리(D3/Chart.js 등) 사용 — 02§1 "Node 빌드 없음" 제약과 20§7 선택(pandas+matplotlib Agg, 서버사이드 PNG) 을 따름
- 그래프 종류 사용자 커스터마이징(차트 타입 선택 등) — 01§5 수용 기준에 없음, 범위 추가하지 않음
