# FR-005 루프 일시정지/재개

## 1. 사용자 스토리
AI-DLC 운영자로서 실행 중인 루프를 일시정지하고 다시 재개하고 싶다, 진행 중인 Task 를 망가뜨리지 않고 멈추기 위해. (01 §5 원문)
- 01 §10 결정: 같은 세션이 일시정지 상태로 기다리다가, 대시보드에서 재개하면 자동으로 남은 반복을 이어간다. `/aidlc-run` 을 다시 입력하지 않는다.
- 00 Q5: 최대 일시정지 기본 2시간(설정 가능), 초과 시 루프를 정상 종료하고 STM 은 건드리지 않는다.

- KPI: 직접 KPI 없음. 10 §6 MVP 성공 기준 3(실제 `/aidlc-run 3` 리허설, 수동 복구 0건)과 10 §3 "안전한 일시정지" 지표(재개 성공률 100%).
- API: `GET /api/v1/control`, `POST /api/v1/control/pause`, `POST /api/v1/control/resume` (20 §5 F3). 대시보드의 유일한 쓰기 = `workspace/memory/.control.json`(D-04).
- 루프 쪽: `aidlc.py loop-start / loop-check / wait-resume / loop-end` 와 exit code 0/10/20/2/64/1(D-09, loop-cli.md). 스킬은 exit code 로만 분기.

## 2. 규칙
### 2.1 화면 상태 판정 (ADR-004 §4 표 그대로, "control" = seq > baseline_seq 인 최신 요청)
| # | loop-status | control | heartbeat | 화면 라벨 (정확한 문구) | 추가 표시 |
|---|-------------|---------|-----------|--------------------------|-----------|
| V1 | 없음 / `ended` | - | - | `루프 없음` | 마지막 `ended_reason` 문구(§2.3), 남은 반복이 있으면 "`/aidlc-run <남은 수>` 로 이어서 실행" |
| V2 | `running` | `pause` | - | `일시정지 요청됨 (현재 Task 진행 중)` | 진행 `done/total` |
| V3 | `running` | `running` / 없음 | - | `실행 중` | 진행 `done/total`, 세션 활동 = 최근 JSONL 기록 시각 |
| V4 | `paused` | `pause` | ≤ 120 s | `일시정지됨 (세션 대기 중)` | 일시정지 경과, 남은 허용 시간(`max_pause_sec − 경과`) |
| V5 | `paused` | `running` | ≤ 120 s | `재개 요청됨` | - |
| V6 | `paused` | - | > 120 s | `세션 없음` | "대기하던 세션이 사라졌습니다 — `/aidlc-run <남은 수>` 로 다시 실행하세요" |

- 남은 수 = `iterations_total − iterations_done`.
- `running` 상태에서는 heartbeat 나이로 세션 생존을 판정하지 않는다(D-11).
- 화면 라벨은 위 문구를 그대로 쓴다(qa 는 문구 포함 여부로 검증).

### 2.2 버튼
| 상태 | 일시정지 버튼 | 재개 버튼 |
|------|---------------|-----------|
| V1 루프 없음 | 비활성 + 툴팁 "실행 중인 루프가 없습니다" | 숨김 또는 비활성 |
| V2 | 비활성(이미 요청됨) | 활성 (요청 취소 = resume) |
| V3 | 활성 | 비활성 |
| V4 | 비활성 | 활성 |
| V5 | 활성 (다시 일시정지) | 비활성 |
| V6 | 비활성 | 비활성 (재개할 세션 없음) |
- `POST /pause` 는 loop-status 가 `running`/`paused` 일 때만 허용, 아니면 409 `NO_ACTIVE_LOOP`. `POST /resume` 은 언제나 허용(멱등, ADR-004 §4).
- 본문 `{}` 또는 `{"max_pause_sec": 600~86400}`, 범위 밖은 422 `VALIDATION_ERROR`. 기본 7200(2시간). resume 은 이전 `max_pause_sec` 를 유지.

### 2.3 종료 사유 문구 (V1)
| ended_reason | 문구 |
|--------------|------|
| `done` | `완료 — N회 반복을 모두 마쳤습니다` |
| `blocked` | `막힘으로 종료 — STM 의 blocker 를 확인하세요` |
| `no_task` | `선택 가능한 Task 가 없어 종료` |
| `pause_timeout` | `일시정지 상한(H시간) 초과로 종료 — 남은 반복 N회: /aidlc-run N` |

## 3. 수용 기준 (Given/When/Then)
### 3.1 기본 흐름 (01 원문 AC)
- **AC-1 (일시정지 요청)** Given `/aidlc-run 3` 이 실행 중(loop-status `running`, done 0/3)일 때 When 일시정지를 누르면 Then `.control.json` 에 `state: pause`, `seq` = 이전 seq + 1 이 원자적으로 쓰이고(`control.schema.json` 통과), 화면은 5초 이내 V2 `일시정지 요청됨 (현재 Task 진행 중)` 이 된다.
- **AC-2 (현재 Task 완료 후 정지)** Given AC-1 이후 현재 사이클이 7단계(STM 닫기 → cascade 1/3·2/3·필요 시 3/3)를 모두 마쳤을 때 When 스킬이 `loop-check <done>` 을 부르면 Then exit 10 이고, 다음 Task 의 STM 을 열지 않으며 `wait-resume` 대기로 들어간다. 이 시점에 STM `status` 는 `idle`, `Memory.pending()` 은 없음(FR-003 화면 "미처리 cascade 없음").
- **AC-3 (일시정지됨 표시)** Given AC-2 로 `wait-resume` 이 실행 중일 때 Then 화면은 5초 이내 V4 `일시정지됨 (세션 대기 중)` 과 일시정지 경과·남은 허용 시간(기본 2시간 기준)을 보여 준다.
- **AC-4 (재개)** Given V4 일 때 When 재개를 누르면 Then `.control.json` 이 `state: running`, seq +1 로 쓰이고, 진행 중인 `wait-resume` 이 다음 1초 tick 안에 exit 0 으로 반환, 스킬이 남은 반복(3 − done)을 `/aidlc-run` 재입력 없이 이어 간다. 화면은 5초 이내 V3 `실행 중` 이 된다(V5 `재개 요청됨` 은 CLI 가 1초 tick 안에 반응하므로 잠깐 보이거나 건너뛸 수 있다 — 검증은 최종 V3 기준).
- **AC-5 (남은 반복 정확성)** Given 1회 완료 후 일시정지·재개했을 때 Then 루프가 끝나면 `iterations_done = 3`, `ended_reason = done` 이고 실행된 사이클은 정확히 3회다(중복·누락 없음).

### 3.2 경계·예외
- **AC-6 (cascade 중 일시정지)** Given 사이클이 4~7단계(STM 닫기·LTM·Task·Plan 갱신) 진행 중일 때 When 일시정지를 누르면 Then 그 사이클의 cascade 가 끝까지 처리된 뒤에만 정지한다(`loop-check` 는 7단계 후에만 호출, ADR-004 Decision 3). 정지 시점에 미처리 cascade 0, STM `idle`.
- **AC-7 (마지막 사이클 중 일시정지)** Given 마지막 사이클(done = N−1) 진행 중 일시정지를 누를 때 Then 마지막 사이클 뒤에는 `loop-check` 를 하지 않으므로 루프는 정상 종료(`ended_reason = done`)하고 화면은 V1 `루프 없음` + `완료` 문구. 남은 pause 요청은 다음 `loop-start` 의 `baseline_seq` 로 무시된다(AC-12).
- **AC-8 (일시정지 취소)** Given V2(아직 Task 진행 중)일 때 When 재개를 누르면 Then 화면은 V3 `실행 중` 으로 돌아가고 `loop-check` 가 exit 0 이라 루프는 멈추지 않는다.
- **AC-9 (같은 루프에서 재일시정지)** Given 일시정지 → 재개 후 V3 일 때 When 다시 일시정지를 누르면 Then 다음 사이클 경계에서 다시 정지한다(seq 가 매번 증가하므로 최신 요청 기준, loop-cli §7).
- **AC-10 (멱등)** Given V2 에서 일시정지 POST 를 한 번 더 보낼 때 Then HTTP 200, 화면 상태 동일(seq 는 +1, 계약상 허용). Given 루프 없음에서 재개 POST 를 보낼 때 Then HTTP 200(멱등).
- **AC-11 (활성 루프 없음)** Given loop-status 가 없거나 `ended` 이거나 깨졌을 때 When 일시정지 POST 를 보내면 Then HTTP 409 `{"error":{"code":"NO_ACTIVE_LOOP",...}}`, `.control.json` 은 바뀌지 않고 화면은 V1, 일시정지 버튼 비활성. CLI 쪽 `loop-check`·`wait-resume`·`loop-end` 는 활성 루프가 없으면 아무것도 쓰지 않고 exit 0(`NO_LOOP`, D-10).
- **AC-12 (이전 루프의 남은 요청 무시)** Given 이전 루프에서 남은 `.control.json` `state: pause`(seq 7) 일 때 When 새 `/aidlc-run 2` 가 `loop-start` 하면 Then `baseline_seq = 7` 이고 첫 `loop-check` 는 exit 0, 화면은 V3 `실행 중`(V2 아님).
- **AC-13 (일시정지 상한 초과)** Given 일시정지 1회(episode)가 `max_pause_sec`(기본 7200 s)를 넘을 때 Then `wait-resume` 이 exit 20, loop-status `state: ended`, `ended_reason: pause_timeout`, 스킬은 루프를 정상 종료 보고(남은 반복 수 안내). STM 은 바뀌지 않는다(일시정지 시점과 해시 동일). 화면은 V1 + `일시정지 상한(2시간) 초과로 종료 — 남은 반복 N회: /aidlc-run N`.
- **AC-14 (상한은 episode 기준)** Given `wait-resume` 이 `--max-wait` 마다 exit 10 으로 여러 번 반복 호출될 때 Then `paused_since` 는 첫 진입 시각을 유지하고 상한은 그 시각부터 계산된다. 재개 후 다시 일시정지하면 `paused_since` 는 새로 시작한다(D-10).
- **AC-15 (상한 설정)** Given `POST /pause {"max_pause_sec": 600}` 일 때 Then 상한 600 s 로 동작하고 남은 허용 시간이 600 s 기준으로 표시된다. Given 599 또는 86401 일 때 Then 422 `VALIDATION_ERROR`, 파일 무변경.
- **AC-16 (대기 중 세션 사라짐)** Given V4 에서 VSCode 창/세션을 닫아 heartbeat 갱신이 멈출 때 Then `heartbeat_age > 120 s` 가 된 뒤 5초 이내(감지 ≤ 2분 + 5초, QS-11) 화면이 V6 `세션 없음` 과 `/aidlc-run <남은 수>` 안내로 바뀐다. 파일 변경이 없어도 서버가 120 s 경계에서 `control` topic 을 발행한다.
- **AC-17 (running 중 heartbeat 오래됨)** Given loop-status `running` 이고 `heartbeat_at` 이 30분 전(긴 Task)일 때 Then 화면은 V3 `실행 중` 그대로이며 `세션 없음` 으로 바꾸지 않는다(D-11).
- **AC-18 (제어 파일 깨짐)** Given `.control.json` 이 깨졌을 때 Then CLI `loop-check`·`wait-resume` 은 exit 2, 스킬은 경고 한 줄 후 **계속 진행**(일시정지하지 않음), 대기 중이었다면 재개된다. 화면 제어 패널은 "제어 파일을 읽을 수 없음 — 일시정지를 다시 누르면 새로 씁니다" 경고(`meta.status = partial`). 다음 POST 는 이전 seq 를 0 으로 보고 새 파일을 쓴다(loop-cli §7, 단 STM §5 질문 참고).
- **AC-19 (loop-status 깨짐)** Given `loop-status.json` 이 잘린 JSON 일 때 Then 제어 패널 `meta.status = error` "루프 상태를 읽을 수 없음", 일시정지 POST 는 409 `NO_ACTIVE_LOOP`, HTTP 500 0건.
- **AC-20 (쓰기 실패)** Given `.control.json` 쓰기가 실패할 때(권한 등, 테스트 주입) Then HTTP 500 `CONTROL_WRITE_FAILED`, 화면 "일시정지 요청을 저장하지 못했습니다", 기존 파일 손상 없음(원자적 교체).
- **AC-21 (단일 작성자)** Given 모든 시나리오일 때 Then 대시보드는 `.control.json` 만 쓰고(`loop-status.json`·STM·tasks 무변경), CLI 는 `.control.json` 을 절대 쓰지 않는다(D-04, S-10 의 허용 예외는 `.control.json` 추가뿐).
- **AC-22 (Hook 영향 없음)** Given `.control.json`·`.monitor/` 존재 여부만 다른 두 workspace 일 때 Then `Memory.pending()`·`summary()` 결과가 같고 `.cascade-state.json` 은 바뀌지 않는다(ADR-004 Decision 6).
- **AC-23 (자동 갱신 — FR-008 P1 최소)** Given 대시보드가 열려 있을 때 When `.control.json`·`loop-status.json` 이 바뀌면 Then 5초 이내 제어 패널이 갱신된다(`control` topic). SSE 실패 시 5초 폴링으로 같은 결과.

## 7. 범위 밖
- 실행 중인 Task 를 즉시 중단(강제 정지). 일시정지는 항상 Task 경계에서만.
- 화면에서 `/aidlc-run` 시작·반복 수 변경·Task 선택.
- 세션이 사라진 뒤 대시보드가 새 세션을 띄워 자동 재개(V6 는 안내만).
- 여러 루프·여러 저장소 동시 제어.
- 원격에서 제어(127.0.0.1 전용, 인증 없음).
