# FR-004 Claude 사용량

## 1. 사용자 스토리
AI-DLC 운영자로서 VSCode 에 연결된 Claude Code 의 사용량을 보고 싶다, 한도에 걸리기 전에 조절하기 위해. (01 §5 원문)

- KPI: **KPI-01 Q3 "5시간 한도를 몇 % 썼고 언제 초기화되나"** 의 유일한 답. 5시간 한도 %·초기화 시각을 첫 화면 상단 행에 둔다.
- API: `GET /api/v1/usage/summary`, `GET /api/v1/usage/timeseries?range=&bucket=&group=&tz_offset_min=` (20 §5).
- 데이터: 한도·비용 = status line 스냅샷 `workspace/memory/.monitor/claude-status.json`(ADR-003), 토큰 = 이 저장소의 Claude Code JSONL `usage` 필드만(ADR-002, Q2·Q7).

## 2. 규칙
- **한도 %**: `rate_limits.five_hour.used_percentage`, `rate_limits.seven_day.used_percentage`(0~100). 화면은 정수로 반올림(0.5 는 올림) 하고 `%` 를 붙인다. 계정 전체 기준 값임을 툴팁으로 안내(A13).
- **초기화 시각**: `resets_at`(Unix epoch 초) → PC 로컬 시간 `HH:mm`(오늘이 아니면 `M/D HH:mm`) + 남은 시간(`N시간 M분 후`).
- **세션 비용**: `cost.total_cost_usd` → `$` + 소수 둘째 자리, 라벨 "세션 비용(추정)". FR-009 예상 비용과 별개(M2).
- **스냅샷 시각**: `captured_at` 경과를 항상 표시(`N분 전 기준`, A5). 10분 초과 = `SNAPSHOT_STALE`(ADR-003).
- **토큰 집계**: 이 저장소 프로젝트 디렉터리만(라벨 "이 프로젝트 기준", A13). 토큰 4종(input, output, cache_creation_input, cache_read_input), requestId 중복 제거 last-wins(D-02). 기대값은 qa 오라클(`reference_parser.aggregate`)·생성기(`JsonlManifest.expected_buckets`)와 3자 대조(D-17).
- **그래프**: 기본 = 최근 24시간, 1시간 단위, 모델별 스택(A14·Q9). 기간 선택 5h / 24h / 7d / 30d(30d 는 일 단위)는 P1 목표이며, 일정 지연 시 P2 로 이월할 수 있다(10 §7 최상위 3 대응). 시간대는 PC 로컬.
- **요약 수치**: 오늘·현재 5시간 구간의 토큰 4종, 캐시 적중률(20 §5 `/usage/summary`).
- **개인정보**: 대화 본문·도구 입출력·경로·sessionId·`transcript_dir_name` 은 응답·SSE·로그 어디에도 나오지 않는다(NFR-003, privacy.md, D-13).

## 3. 수용 기준 (Given/When/Then)
### 3.1 한도·비용 (스냅샷)
- **AC-1 (정상)** Given 스냅샷 `normal`(five_hour 42.4%, seven_day 17.5%, resets_at 있음, cost 1.234) 일 때 When 사용량 패널을 보면 Then `5시간 42%`, `7일 18%`, 각 초기화 시각(로컬)과 남은 시간, `세션 비용(추정) $1.23`, "N분 전 기준" 이 표시된다.
- **AC-2 (반올림 경계)** Given used_percentage 42.5 → `43%`, 0 → `0%`, 100 → `100%`.
- **AC-3 (rate_limits 없음)** Given 스냅샷 `no_rate_limits`(`rate_limits: null`) 일 때 Then 한도 영역에 "한도 정보 없음 — Pro/Max 구독의 CLI 세션에서 첫 응답 이후 표시" 가 나오고, 토큰 집계·그래프는 정상 표시, `limits_available = false`, HTTP 200.
- **AC-4 (창 하나만 없음)** Given `five_hour` 는 있고 `seven_day: null`(또는 `used_percentage: null`) 일 때 Then 5시간은 값, 7일은 "정보 없음".
- **AC-5 (스냅샷 없음)** Given 스냅샷 파일이 없을 때(`none`) Then AC-3 과 같은 "한도 정보 없음" 안내 + 세션 비용 `-` + 토큰 집계 표시. VSCode 확장에서 statusLine 이 동작하지 않는 경우의 안내(A5·Q13) "CLI 세션에서 실행하면 한도가 표시됩니다" 가 함께 나온다.
- **AC-6 (오래된 스냅샷)** Given `captured_at` 이 30분 전(`stale`) 일 때 Then 한도 값은 표시하되 "30분 전 기준 — 최신 값이 아닐 수 있음" 경고와 `SNAPSHOT_STALE` 코드가 붙는다. 10분 이하에서는 경고가 없다(경계: 600초 = 경고 없음, 601초 = 경고).
- **AC-7 (초기화 시각 지남)** Given `resets_at` 이 현재보다 과거일 때 Then 남은 시간 대신 "초기화 시각 지남 — 새 응답 후 갱신" 이 표시된다.
- **AC-8 (깨진 스냅샷)** Given 스냅샷이 잘린 JSON 이거나 `schema ≠ 1` 일 때(`broken`) Then 한도 영역만 "한도 정보를 읽을 수 없음"(`SOURCE_PARSE_ERROR`), 토큰 집계는 정상, 패널 `meta.status = partial`, HTTP 500 0건.

### 3.2 토큰 집계·그래프 (JSONL)
- **AC-9 (집계 정확도)** Given `claude_home` fixture(중복 requestId, usage 없는 줄, 깨진 줄, 잘린 꼬리, subagents, 만료 파일, 거대 줄 포함) 일 때 When `/usage/timeseries?range=30d&bucket=hour&group=model` 을 조회하면 Then 모든 버킷의 토큰 4종이 오라클·생성기 기대값과 같다(3자 일치). 거짓 양성 토큰 `777777`·symlink 이탈 토큰 `424242` 는 합계에 없다.
- **AC-10 (중복 제거)** Given 같은 requestId 의 줄 7개(마지막 줄 usage 가 최종값) 일 때 Then 그 응답은 1회, 마지막 줄 값으로 집계된다.
- **AC-11 (기본 그래프)** Given 첫 화면을 열었을 때 Then 토큰 그래프는 최근 24시간·1시간 단위·모델별 스택으로 표시되고 "이 프로젝트 기준" 라벨이 있다.
- **AC-12 (기간 선택 — P1 목표, P2 이월 가능)** Given 기간 `7d` 를 고르면 Then 1시간 또는 일 단위 막대가 7일치, `30d` 는 일 단위 30개. 날짜 경계는 `tz_offset_min` 기준 로컬 자정.
- **AC-13 (프로젝트 디렉터리 없음)** Given 이 저장소의 Claude Code 기록 디렉터리를 찾을 수 없을 때(`with_jsonl=False`) Then 그래프 영역에 "이 프로젝트의 Claude Code 기록을 찾을 수 없음"(`PROJECT_DIR_NOT_FOUND`), 한도 영역은 스냅샷이 있으면 정상 표시, HTTP 200.
- **AC-14 (기록 없음)** Given 디렉터리는 있지만 최근 30일 기록이 0건일 때 Then 그래프 빈 상태 "선택한 기간에 기록 없음", 합계 0.
- **AC-15 (데우는 중)** Given 서버 기동 직후 30일 JSONL 캐시를 데우는 중일 때 Then 패널은 2초 안에 부분 값 + "데우는 중 (NN%)" 을 보여 주고(`meta.status = warming`), 완료(`ready` 이벤트) 후 5초 이내 최종 값으로 바뀐다.
- **AC-16 (요약)** Given fixture 일 때 Then `/usage/summary` 의 오늘·현재 5시간 구간 토큰 4종과 캐시 적중률 = `cache_read / (input + cache_creation + cache_read)`(30 EDA 질문 4 와 같은 정의, 분모 0 이면 `-`) 가 오라클 계산과 같다.

### 3.3 개인정보·안전
- **AC-17 (본문 비노출)** Given 본문 표식이 든 `claude_home` 일 때 When 모든 사용량 REST 응답·헤더·SSE 프레임·로그를 수집하면 Then 표식·경로·`transcript_dir_name` 이 0회 나온다.
- **AC-18 (사전 필터·content 비접근)** Given `"usage":` 가 없는 줄일 때 Then 그 줄은 JSON 파싱되지 않고, 어떤 줄에서도 `message.content` 에 접근하지 않는다.
- **AC-19 (경로 힌트 재검증)** Given 스냅샷 `transcript_dir_name` 이 음성 이름(`..`, 구분자, 개행 등)이거나 `~/.claude/projects/` 직속 하위가 아닌 곳으로 해석될 때 Then 힌트를 무시하고 폴백 해석, 실패 로그에 값이 없다.

### 3.4 갱신·첫 화면
- **AC-20 (자동 갱신 — FR-008 P1 최소)** Given 대시보드가 열려 있을 때 When 스냅샷 파일이 바뀌거나 JSONL 에 새 응답이 추가되면 Then 5초 이내 한도·토큰 표시가 바뀐다(`usage` topic). `captured_at` 이 10분 경계를 넘으면 새 파일 쓰기가 없어도 5초 이내 stale 경고가 나타난다.
- **AC-21 (첫 화면)** Given 첫 화면을 열었을 때 Then 5시간 한도 %와 초기화 시각(또는 "한도 정보 없음" 안내)이 스크롤·클릭 없이 상단 행에 보인다(KPI-01 Q3, UAT).
- **AC-22 (성능)** Given Task 100개 + 30일 JSONL fixture 일 때 Then 접속 → 사용량 패널 표시(값 또는 warming) ≤ 2초(P-01), JSONL 1 MB 추가 후 반영 ≤ 5초(P-02).

## 4. 예외·경계 흐름
| 상황 | 기대 동작 |
|------|-----------|
| 스냅샷 없음 / `rate_limits` 없음 | AC-5 / AC-3. 토큰만 + "한도 정보 없음" 안내 100% |
| 스냅샷 깨짐 / schema 불일치 | AC-8 |
| 스냅샷 오래됨 | AC-6 |
| 여러 세션이 동시에 스냅샷을 씀 | 마지막 쓰기 값 표시(ADR-003 last writer wins). `session_hash` 로 세션 구분 표시는 하지 않아도 된다 |
| JSONL 디렉터리 없음 / 기록 0건 | AC-13 / AC-14 |
| JSONL 깨진 줄·UTF-8 아님·잘린 꼬리·`message.usage` 비 dict | 그 줄만 건너뜀, 경고 건수만(`partial` 아님 — 정상 데이터 일부), 500 0건 |
| 콜드 스타트 | AC-15 (warming) |
| 빈 workspace | 사용량 패널은 workspace 와 무관하게 동작하되 스냅샷 경로가 없으므로 AC-5 |

## 5. 화면 상태
| meta.status | 화면 |
|-------------|------|
| ok | 5h·7d 게이지(%·초기화 시각·남은 시간), 세션 비용, 스냅샷 경과, 토큰 시계열 스택 차트, 모델별 표, 오늘·5시간 토큰 4종, 캐시 적중률 |
| partial | 가능한 영역은 값, 문제 영역은 안내(예: 한도 "한도 정보를 읽을 수 없음", 그래프는 정상) |
| empty | "사용 기록이 없습니다" (스냅샷·JSONL 모두 없음) + "한도 정보 없음" 안내 |
| error | "사용량을 읽을 수 없음" + 오류 코드. 다른 패널 정상 |
| warming | 부분 값 + "데우는 중 (NN%)" 진행률 |
