# AI-DLC Monitor

AI-DLC 저장소의 진행 상태(파이프라인 단계, Task, 메모리, Claude 사용량)를 브라우저 한 화면에서 보고, 실행 중인 `/aidlc-run` 루프를 일시정지·재개하는 **내 PC 전용** 대시보드입니다.

- 버전 0.1.0 (P1 / M1 범위: 읽기 대시보드 + 일시정지·재개)
- 로그인·원격 접속·다중 저장소·화면에서 문서 편집은 지원하지 않습니다.

## 1. 설치와 실행

필요한 것은 **Python 3.11 이상** 하나입니다. Node/npm 은 필요 없습니다(빌드된 화면이 저장소에 포함되어 있습니다). 처음 한 번은 패키지를 받기 위해 인터넷 연결이 필요합니다.

저장소 루트(`run.py` 가 있는 폴더)에서 아래 중 하나를 **한 번** 실행합니다. 가상환경 생성, 패키지 설치, 서버 기동, 브라우저 열기를 알아서 합니다.

| 환경 | 명령 |
|------|------|
| Windows | 탐색기에서 `run.bat` 더블클릭 (또는 터미널에서 `run.bat`) |
| macOS / Linux | `./run.sh` (또는 `bash run.sh`) |
| 어디서나 | `python run.py` (Windows 는 `py -3 run.py`) |

옵션 (`python run.py --help` 로 확인, 세 런처가 같은 옵션을 받습니다):

| 옵션 | 뜻 |
|------|-----|
| `--port N` | 포트 지정 (기본 8765). 환경 변수 `AIDLC_MONITOR_PORT` 로도 지정할 수 있고, 둘 다 있으면 `--port` 가 우선합니다. |
| `--no-browser` | 브라우저를 열지 않고 서버만 시작합니다. |

동작 요약:

1. Python 3.11+ 를 찾습니다. 없거나 낮으면 설치 안내를 출력하고 끝납니다(`run.bat` 은 창이 바로 닫히지 않게 `pause` 합니다).
2. `monitor/.venv` 를 만들고 `monitor/backend/requirements.txt` 를 설치합니다. 두 번째 실행부터는 `설치 생략` 이 출력되고 바로 시작합니다.
3. 서버가 `http://127.0.0.1:8765/` 에서 뜨면 기본 브라우저가 열립니다. 8765 를 다른 프로그램이 쓰고 있으면 다음 빈 포트로 시작하고 콘솔에 실제 주소를 출력합니다. 이미 대시보드가 떠 있으면 서버를 새로 띄우지 않고 브라우저만 엽니다.
4. 끝내려면 실행한 콘솔에서 `Ctrl+C` 를 누릅니다.

> 측정 참고: 아직 사람이 직접 잰 정식 설치 리허설(KPI-02)은 하지 않았습니다. Linux 컨테이너에서 잰 참고값은 [UAT 체크리스트 §6.7](../workspace/project/uat/uat-checklist.md) 에 있습니다. 첫 실행이 "5분 이내" 라는 목표의 사람 측정 결과는 **미검증**입니다.

## 2. 첫 화면 읽는 법

주소창은 `http://127.0.0.1:<포트>/` 여야 합니다. 다른 이름이나 포트로 열면 `BAD_HOST`(400) 로 거절됩니다.

스크롤하지 않아도 보이는 **맨 위 카드 5개**가 핵심입니다.

| 카드 | 알려 주는 것 |
|------|--------------|
| 파이프라인 단계 | 지금 AI-DLC 0~6 단계 중 어디인지, 다음에 실행할 명령 |
| Phase 진행률 | 현재 Phase 의 완료 Task / 전체 Task, 퍼센트 |
| 현재 Task | 진행 중인 Task ID 와 담당 팀, 경과 시간. 진행 중인 Task 가 없으면 `대기` |
| 5시간 한도 | Claude 5시간 사용 한도 사용률(%). 정보가 없으면 `한도 정보 없음` |
| 루프 | `/aidlc-run` 루프 상태(`실행 중`, `일시정지됨 (세션 대기 중)`, `루프 없음` 등)와 반복 진행 수 |

그 아래 패널: 파이프라인 단계 상세와 문서 Gate 3종, 루프 제어(일시정지/재개 버튼), Claude 사용량(5시간·7일 게이지, 토큰 그래프), Plan·Phase 진행률, 메모리 상태(STM/LTM/Tasks 값, 미처리 cascade), Task 목록(Phase·팀·상태 필터).

화면 맨 위 오른쪽 표시:
- `● 실시간` — 변경을 즉시 받는 중. `● 5초 폴링` — 실시간 연결이 안 돼 5초마다 다시 읽는 중. 두 경우 모두 파일이 바뀌면 5초 안에 화면이 갱신되는 것이 목표입니다.
- `사용량 집계 중 NN%` — 서버를 막 켠 뒤 Claude 사용 기록을 읽는 중입니다. 끝나면 사라집니다.
- `⟳` — 모두 다시 읽기.

참고할 점:
- 5시간 한도는 Claude Code 의 status line 신호가 있어야 표시됩니다. 이 저장소는 `.claude/settings.json` 에 status line 이 등록되어 있고, Claude Code 세션에서 첫 응답을 받은 뒤부터 값이 생깁니다. 구독이 아니거나(API 키) 신호가 없으면 `한도 정보 없음` 안내가 나오고, 토큰 집계는 계속 표시됩니다. 실제 세션에서의 동작은 **미검증**입니다(UAT 미실행).
- 맨 위에 경고 줄(⚠)이 보이면 미처리 메모리 cascade, 막힌 Task, 한도 80% 이상 중 하나입니다.
- 일부 데이터 파일이 없거나 깨져도 화면은 뜨고, 해당 패널에만 안내가 나옵니다.

## 3. 일시정지 / 재개

`/aidlc-run N` 으로 여러 Task 를 이어서 실행하는 중에, 현재 Task 를 망가뜨리지 않고 쉬었다 가고 싶을 때 씁니다.

1. Claude Code 에서 `/aidlc-run 3` 처럼 루프를 시작합니다. 루프 카드가 `실행 중` 이 됩니다.
2. **루프 제어** 패널에서 `⏸ 일시정지` 를 누릅니다. 상태가 `일시정지 요청됨 (현재 Task 진행 중)` 이 됩니다. 진행 중인 Task 는 **끝까지** 마치고(메모리 cascade 처리 포함) 다음 Task 를 시작하지 않습니다.
3. Task 가 끝나면 `일시정지됨 (세션 대기 중)` 이 되고 남은 허용 시간(기본 2시간)이 보입니다. Claude Code 세션은 닫지 말고 그대로 두세요.
4. `▶ 재개` 를 누르면 `/aidlc-run` 을 다시 입력하지 않아도 남은 반복을 이어서 실행합니다.

알아 둘 점:
- 일시정지는 항상 Task 경계에서만 멈춥니다. 실행 중인 Task 를 즉시 끊지 않습니다.
- 일시정지가 2시간(기본)을 넘으면 루프가 정상 종료되고 `일시정지 상한(2시간) 초과로 종료 — 남은 반복 N회: /aidlc-run N` 이 표시됩니다. 작업 중이던 메모리(STM)는 건드리지 않습니다.
- 대기하던 세션이 사라지면(창을 닫는 등) 약 2분 안에 `세션 없음` 으로 바뀌고 `/aidlc-run <남은 수>` 로 다시 실행하라는 안내가 나옵니다.
- 루프가 없을 때는 일시정지 버튼이 비활성입니다.
- 이 화면이 쓰는 파일은 `workspace/memory/.control.json` **하나뿐**입니다(Git 에 커밋되지 않습니다).
- 실제 Claude Code 세션에서의 일시정지/재개 리허설(UAT R-1~R-3)은 아직 하지 않았습니다 — **미검증**. 자동 테스트와 서브에이전트 환경에서의 대기 측정(`wait-resume` 120/300/540초)만 통과했고, 사용자 메인 세션과 Windows 는 측정 전입니다.

## 4. 문제 해결

| 증상 | 안내 |
|------|------|
| 서버가 시작되지 않음 ("서버가 시작되지 않았습니다") | [server-wont-start](../workspace/project/ops/runbooks/server-wont-start.md) |
| 포트가 이미 사용 중 / 다른 앱이 열림 | [port-in-use](../workspace/project/ops/runbooks/port-in-use.md) |
| 5시간 한도 %가 안 나옴 | [statusline-not-running](../workspace/project/ops/runbooks/statusline-not-running.md) |
| 일시정지가 풀리지 않음 / `세션 없음` | [pause-not-releasing](../workspace/project/ops/runbooks/pause-not-releasing.md) |
| 사용량 집계가 오래 걸림 | [warmup-slow](../workspace/project/ops/runbooks/warmup-slow.md) |

서버가 살아 있는지 빠르게 보려면 `curl -s http://127.0.0.1:8765/api/v1/health` (응답에 `"app":"aidlc-monitor"` 가 있으면 대시보드입니다). 로그 형식과 금지 항목은 [logging.md](../workspace/project/ops/logging.md) 를 보세요.

## 5. 보안 약속

- **내 PC 안에서만**: 서버는 `127.0.0.1` 에만 바인딩됩니다. 같은 네트워크의 다른 PC 에서는 접속할 수 없고, 설정으로 바꿀 수도 없습니다. 로그인은 없습니다.
- **읽기 전용**: 화면은 `workspace/` 문서와 Claude Code 사용 기록을 읽기만 합니다. 쓰는 파일은 일시정지/재개 요청을 담는 `workspace/memory/.control.json` 하나뿐이며, 요청으로 파일 경로를 받지 않습니다. (런처는 별도로 `monitor/.venv` 를 만듭니다. 전역 Python 패키지나 `~/.claude` 는 바꾸지 않습니다.)
- **대화 본문에 접근하지 않음**: 사용량은 Claude Code 기록(JSONL)의 토큰 수치만 읽습니다. 대화 내용(`message.content`)은 읽지도, 화면·응답·로그에 내보내지도 않습니다. 인증 파일(`~/.claude` 의 자격 증명)은 읽지 않습니다.
- **다른 사이트가 요청을 보낼 수 없음**: 허용된 Host 가 아니거나(`BAD_HOST`), 쓰기 요청이 같은 출처의 JSON 이 아니면(`FORBIDDEN_ORIGIN`) 거절합니다.
